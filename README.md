# 医序｜多学科就医智助系统

比赛交付版，整理日期：2026-10-13。

正式名称：多学科就医智助系统。对外品牌：医序；对外完整名称：医序｜多学科就医信息协作平台。

## 1. 产品简介与定位

多学科就医智助系统面向复杂病例的会诊准备、医生协作审核与后续资料复核，针对病历资料分散、重复整理耗时、专科意见难协调等问题，构建患者端与医生端协同的信息辅助平台。对外品牌名称为“医序”。

患者提交病情描述和已有资料后，系统通过文本隐私处理、病例结构化及规则与大模型协同分析，形成病例摘要、病程时间线、资料缺口、就医方向与路径，以及带来源的专科 AI 参考意见。医生依次完成病例核对、AI 资料审阅和分流确认，根据需要生成 AI 会诊模拟、记录实际会诊结论、处理关键审核条目与分歧，最后预览并发布患者报告。

后续新增资料进入后，系统重新评估就医方向与路径，标识受影响的专科意见和待复核条目，保留历史报告与审核记录，支持病例持续更新和过程追溯。系统保留医生最终判断权，旨在减少重复资料整理，使意见处理和后续追踪更清晰。

**能力边界：**系统提供资料整理与协作审核辅助，不提供确定性诊断、处方、药物剂量或自动治疗决策。AI 专科分析、AI 会诊模拟与实际医生会诊分别记录。当前账号体系用于比赛演示，账号登录不能证明真实医师身份；本项目的测试结果也不能作为临床准确率或实际节时效果的证明。

## 2. 两端功能与业务流程

### 患者端

1. 注册或登录患者账号，填写病情描述、已有检查和主要问题；可上传病历图片辅助录入。
2. 查看文本脱敏预览并确认提交，核对规则画像、年龄与性别，补答高价值追问。
3. 查看就医准备资料和建议方向，将病例提交至主责科室等待审核；目标科室暂无可用医生时会明确提示。
4. 查看医生发布的最终报告，打印或回看历史发布版本；继续记录任务进度并提交新检查、症状变化、复查安排等资料。

游客只能使用限量规则体验，不创建正式病例，不进行模型分析或医生报告发布。

### 医生端

工作台按“病例摘要 → AI 资料包 → 分流确认 → MDT 协作与会诊记录 → 报告审核”组织流程。医生确定主责与协同科室、单科或正式 MDT 处理方向，以及本次共同处理的目标。AI 模拟仅作为参考；正式 MDT 的实际参与人员、结论、未解决事项和后续安排需要独立记录。

审核对象包括专科整体 AI 意见、关键医疗安排以及共识／分歧条目。系统区分必审、抽查与自动处理责任，支持接受、修改、驳回、暂不确定和请求补资料。修改与驳回需要理由；分歧处理需要决定或明确后续安排；关键必审项不能用批量接受绕过。

发布前生成预览，病例、审核决定或最终建议发生变化后需要重新预览。已发布轮次禁止直接修改审核决定和分歧处理。补充资料进入复核后，医生重新核对并发布新版本，旧发布快照保持不变。患者读取已发布报告时使用对应的保存快照。

### 增量复核与数据一致性

- 初始病史、主要问题、已保存的有效追问答案和新增资料共同组成分析输入；同步分析、延迟 MDT、后台增强及重试共用输入构造逻辑。
- 表单年龄与性别单独保存。后台增强或规则降级保留这些字段；正文冲突会标记待核对。性别仅接受男、女、其他、未知或留空，两个请求别名 `gender`、`sex` 一并校验。
- 未变化任务继承稳定编号、状态与操作历史；空答案或相同答案重复提交保持幂等。可明确匹配的已完成任务若内容改变，通过状态机记录为需重做，避免清空进度或混用任务编号。
- 检查项目仅被提及、未做、待做或结果尚未出时保留缺口；明确提供结果才填补，并记录填补依据。否定的追问回答也不会被当作已补齐检查资料。

## 3. 实现方式、权限与隐私

技术栈为 Python 3.10+、Flask、SQLite、原生 HTML/CSS/JavaScript。页面使用本地静态资源，不需要前端构建。核心分析采用 S1 规则识别、S2 模型受限发言、S3 确定性编排；病例、更新、决定、任务操作、报告版本和审计记录在本地持久化。

患者只能管理自己的病例。医生需具备账号权限和逐病例授权；主责、协同及协调职责分别约束业务操作。普通共享授权只授予协同职责，主责身份由正式提交／分流业务确定并留痕。显式配置的总审账号可访问全部病例。审核、分歧处理和发布的责任账号、角色、科室由登录会话确定，客户端提供的显示名称不能冒写责任身份。

文本进入分析前进行隐私检测和打码；预览凭证绑定患者账号，短期、一次性使用。模型发送边界再次检查敏感身份信息，阻止未清除的阻断型信息外发。规则只能处理已定义的信息模式，上传者仍应避免提交不必要的身份信息。

**图片识别的处理方式不同：**配置视觉模型后，上传图片会发送至配置的外部服务，不会自动遮盖图片中的姓名、电话等信息。上传前应手动遮盖身份信息，识别后核对文字。识别服务不可用时可手动录入。

没有模型密钥时只运行本地规则链路，专科模型分析明确跳过；重试和 AI 会诊模拟返回未配置提示，批量分析给出跳过原因，不生成虚假任务。实际医生会诊记录仍可填写。

默认服务只监听本机、关闭调试。会话、预览凭证和后台任务为进程内状态；服务重启可能使会话失效或任务需要恢复。真实机构认证、分布式任务队列及完整生产部署需要另行建设和验证。

## 4. 安装、配置与运行

在代码目录打开 PowerShell：

```powershell
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r backend\requirements.txt

# 首次配置时复制模板；已有 .env 时不要覆盖
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

编辑 `.env`，替换示例密码，至少设置：

```dotenv
APP_PATIENT_USERNAME=patient
APP_PATIENT_PASSWORD=your-strong-patient-password
APP_DOCTOR_USERNAME=doctor
APP_DOCTOR_PASSWORD=your-strong-doctor-password
APP_DOCTOR_DEPARTMENT=endocrinology
APP_DOCTOR_ACCESS_SCOPE=department
APP_AUTO_ASSIGN_REVIEWER=false
APP_REVIEWER_MODE=simulation
APP_HOST=127.0.0.1
APP_PORT=5000
APP_DEBUG=false
AI_API_KEY=
```

单医生演示中，`endocrinology` 表示内分泌科。多医生可配置 `APP_DOCTOR_ACCOUNTS_JSON`，每个医生绑定标准科室；`access_scope=all` 用于明确设置的总审账号。账号密码也支持 `APP_*_PASSWORD_HASH`。默认没有可直接使用的代码内置密码。

启用模型时，按服务提供方填写 `AI_API_KEY`、`AI_API_URL`、`AI_MODEL_NAME`；图片识别还需填写服务支持的 `AI_VISION_MODEL_NAME`。模板中的地址和模型名只是配置示例，需要实际服务验证。密钥与 `.env` 不应进入提交包。

```powershell
Set-Location backend
& '..\.venv\Scripts\python.exe' app.py
```

入口：[首页](http://127.0.0.1:5000/)、[患者端](http://127.0.0.1:5000/patient)、[医生端](http://127.0.0.1:5000/doctor)。在 macOS/Linux 中使用 `.venv/bin/python` 运行对应命令。

## 5. 测试与验收

在 `backend` 目录运行完整回归和前端逻辑检查：

```powershell
& '..\.venv\Scripts\python.exe' -X utf8 -m unittest discover -s tests -v
node verify_frontend_logic.mjs
```

保持服务运行，在另一终端的 `backend` 目录执行以下 HTTP 验收。使用新建的测试账号和合成病例；脚本会创建病例、填写审核决定及发布报告，应在隔离测试数据库中执行：

```powershell
& '..\.venv\Scripts\python.exe' -X utf8 verify_doctor_http.py
node verify_report_render.mjs
& '..\.venv\Scripts\python.exe' -X utf8 verify_e2e_cases.py --fast
& '..\.venv\Scripts\python.exe' -X utf8 verify_update_http.py
```

账号读取项目 `.env` 或环境变量；环境变量优先。报告脚本自动读取 `.env` 需要支持 `process.loadEnvFile` 的 Node.js（建议使用本次验证的 Node.js 24）；较旧版本需要提前设置账号环境变量。服务使用其他地址时设置 `APP_BASE_URL`。

`backend/tests/test_audit_regressions.py` 包含针对 F01—F08 的交叉流程回归，验证正确行为，而非继续断言缺陷存在。覆盖发布快照和复核新版本、可信责任身份、答案输入一致性、任务进度与幂等性、检查缺口语境、人口学字段保留、共享职责和性别隐私约束。

本次验证环境为 Windows、Python 3.12.14、SQLite 3.53.1、Node.js 24.20.0。测试包括规则模式和离线假模型模式，不调用真实外部模型。真实模型返回质量、联网异常、视觉识别效果及临床效果不在此次离线验证结论内。
