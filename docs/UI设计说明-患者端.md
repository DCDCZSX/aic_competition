# 患者端 UI 设计说明（比赛版 v-competition）

> 配套：《产品开发规格书-比赛版v-competition.md》（本文是它的 §2 P0 演示链路 + §5 schema 的界面层展开）
> 形态：本地 Web 应用（浏览器界面）；**本文只描述设计，不包含任何实现代码**。
> 范围：患者端主流程 = **登录 → ①填写情况 → ②核对资料 → ③查看建议 → ④查看医生结果**。第四阶段提供医生审核状态、最终建议、报告和打印。
> 2026-10-07 当前实现：医生完成审核并填写最终建议后统一发布，患者通过“刷新医生结果”或“我的病历”获取最新结果；已发布建议包含发布者、时间和版本，并进入打印报告。下方早期报告图例只保留为视觉参考。
> 2026-10-07 滚动布局修复：患者顶栏、病例横栏、左侧导航和主内容同处文档流，共用页面滚动；左栏不再固定于视口或拥有独立纵向滚动。桌面两栏起始位置对齐，≤1000px 时导航位于主内容上方，步骤条内部可横向滚动。无病例时上下文行正确隐藏，已有病例横栏继续保留。
> 风格：与医生端 UI 说明共用一套 **冷静专业医疗风** token（见《UI设计说明-医生端审核台.md》§1，本文直接沿用：主蓝 `#1B5E8A`、背景 `#F4F7FA`、语义色一致），患者端仅密度更松、文案更口语化、面向中老年用户大字化。
> 说明：**AI MDT 逐科发言/共识分歧等完整过程内容归属医生端**（见医生端 UI 说明"屏 E：MDT 会诊审阅台"）。患者端先展示分析完成后的各科摘要卡，再展示医生已发布的最终建议；最终建议由医生填写。登录页（屏 0 角色选择）两稿共用，此处不再重复线框。

---

## 1. 患者端一句话体验

> 患者提交散乱的病历 → 核对画像并回答关键问题 → 查看就医方向和 AI 参考摘要 → 医生审核、填写最终建议并发布 → 患者查看医生结果和报告。

## 2. 患者端流程地图（对应规格书 §2 P0 链路）

```
[登录页·进入患者端] ─▶ ① 填写情况（就医目标 + 病情资料）
   ─▶ ② 核对资料（结构画像确认 + 必要追问；脱敏在后台自动完成）
   ─▶ ③ 查看建议（分诊方向 + 就医路径 + AI 多学科参考）
   ─▶ ④ 查看医生结果（未发布状态 / 医生最终建议 + 审核报告 + 打印）
医生工作台：审核 → 填写最终建议 → 发布审核版本 → 患者刷新查看
```
> 说明：逐科发言/共识分歧/证据追溯等完整 MDT 内容属于**医生端**（医生端 UI"屏 E"），患者端 P8 只给结论摘要。
> 导航规则：准备报告可读后，左侧四个阶段允许回看；医生发布是独立状态，不能从患者已就诊或 AI 整理完成推断为已审核。打开或刷新医生结果时重新获取报告，病例列表入口独立读取保存的病例结果。

> 顶栏全程常驻：作品名、病例号、身份条（`患者 · patient` [退出]）和合规角标；四阶段总进度在左侧流程栏，第三阶段的分析细分进度在内容顶部显示。
> 合规元素与医生端一致：任何未过医生审核的分析都带 **"AI 辅助分析 · 尚未经医生审核"** 提示。

**响应式与打印约定（2026-09-15 实现口径，有分档回归测试守着）**：

| 宽度 | 布局 | 关键点 |
|---|---|---|
| ≥1000px | 两轨：左流程导航 + 主工作区 | 顶栏保留病例号和审核状态，病例详情只在当前阶段展示 |
| ≤999px | 单列堆叠，左轨 4 步变**横向可滚动步骤条** | 阶段内容单列；报告目录移到正文上方 |
| ≤640px | 单列 + 页面内边距收窄到 16px | 正文不再被挤成窄条 |
| 打印 | 隐藏顶栏 / 轨道 / 操作条，仅正文 | 完整报告的 13 个折叠段**自动全部展开**（打印后恢复原折叠状态），折叠箭头与"展开全部"按钮不打印 |

> **医生端硬约定**：右轨/侧栏里的关键操作必须有主区镜像（如 `#rev-publish` ↔
> `#rev-publish-inline`）——医生端右轨在窄屏会被 `display:none` 收起，没有镜像就等于按钮凭空消失。
> 患者端没有常驻右轨，关键操作直接位于主工作区。`tests/test_responsive_layout.py` 在 8 档宽度上守着这条。

## 3. 逐屏设计说明

### 阶段 1：填写情况（目标与病情资料合并）
> 设计原则：患者在同一个栏目里完成目标选择和资料录入。目标只是帮助系统理解关注点，可以跳过；页面只保留填写时真正需要的提示。

```
┌────────────────────────────────────────────────────────┐
│ ① 填写情况                                                   │
│ 就医目标（选填）                                              │
│                                                         │
│ ┌──────────────────────────────────────────────────┐   │
│ │ 😕 我/家人身体不舒服，不知道先该看哪个科、怎么办     │   │
│ │    推荐选择：多数人都是这种情况                      │   │
│ └──────────────────────────────────────────────────┘   │
│  ▽ 我的情况更特殊一点（可不选）                          │
│    □ 有好几种老毛病，想一起理清楚                        │
│    □ 几个医生说法不太一样，想对比一下                    │
│    □ 要做手术/治疗，想提前把想问的问题准备好             │
│ 病情资料                                                     │
│ [粘贴病历] [表单填写]                                        │
│ [病历文本 / 表单字段]                                        │
│ 主要问题（选填）                                             │
│ ⚠ 请勿填写姓名、身份证号、手机号或住址                       │
│                         [继续 → 核对资料]                    │
└────────────────────────────────────────────────────────┘
```
- 内部仍映射主文档 §5.1 目标与规格书行为类型 A-E，但**界面只讲人话**；术语不出现。
- 特殊场景选项展开后选中的目的：调整追问侧重点、任务排序与展示重点（如选了"手术/治疗"则在追问与任务里多提示术前评估项），**不直接决定分诊结论**（主文档 §5.1 红线）。
- 患者任何时候可返回本阶段修改。
- 对应主文档 §5.2；Tab2 表单 = 精简动态行（症状/既往史/用药/检查），并提供**既往病史快捷点选**（常见慢性病 chip：糖尿病、高血压、冠心病、脑卒中、慢阻肺、肿瘤史等——照顾中老年不擅长打字）。
- **既往病史获取的设计口径（面向"给医院用"的产品定位）**：
  - ✅ 比赛版（演示数据可得）：粘贴病历自动抽取既往史（进 P4 画像）+ Tab2 快捷点选 + 患者自述。
  - 🔜 **远期（需医院 HIS/区域健康档案授权对接，比赛版不做、不宣称）**：患者授权后，系统从院内系统自动带出既往疾病、手术史、用药史与近期检查——这属于主文档"能力边界"与规格书 P2"真实医院对接"项；在演示与答辩材料中**不得声称已实现**，只能作为"应用价值/展望"一句话（防"文档与实现不符"红线，见考古报告）。
- 校验：主诉与主要问题双空 → 阻断提示（规格书 G2）；长度/数值域校验；PII 提示。
- 目标选择和资料录入共用一个底部主按钮，直接进入阶段 2；不再设置“直接开始录入资料”按钮。

### 阶段 2 前置处理：后台自动脱敏
> 患者端不再单独展示“提交前脱敏预览”页面。点击阶段 1 的继续按钮后，系统先在后台完成脱敏检查并生成一次性提交凭证：检测到可直接定位个人的身份信息时停留在阶段 1 提示修改；通过检查后直接创建病例并展示结构化画像。

- 脱敏、PII 拦截和一次性凭证仍保留在后端，不能因为隐藏界面而绕过隐私门槛。
- 患者只有在画像页看到“核对结构化画像”，不需要再确认一次脱敏文本。

### 阶段 2：核对资料（画像与关键问题同屏）
```
┌────────────────────────────────────────────────────────┐
│ ② 核对资料：先看画像，再直接回答关键问题                  │
│ ┌─ 基础 ────────────────────────────────────────────┐   │
│ │ 男 58岁        来源 S-1:12 (hover 显示原文)         │   │
│ ├─ 主诉与症状 ─────────────────────────────────────┤   │
│ │ 视物模糊3月渐重 [原文记载]   下肢浮肿1周 [原文记载]   │   │
│ ├─ 已知疾病 ───────────────────────────────────────┤   │
│ │ 2型糖尿病5年, 控制情况不详 [AI推断·紫标]  ←待确认    │   │
│ ├─ 检查异常 ───────────────────────────────────────┤   │
│ │ 尿蛋白 ++ [原文记载]                               │   │
│ ├─ 用药 ───────────────────────────────────────────┤   │
│ │ 二甲双胍 0.5g bid [原文记载]                       │   │
│ └─ 信息缺口 ───────────────────────────────────────┘   │
│   ⚠ 血糖控制水平不详 · 未提供眼底检查(高价值缺口,将追问)   │
│ [有误? 补充/修正]                                          │
│ 关键问题（最多 3 个，可跳过）                              │
│ Q1 血糖最近控制得怎么样？       [填写] [不清楚/跳过]        │
│ Q2 做过眼底检查吗？             [填写] [不清楚/跳过]        │
│                                      [回答完毕 →]          │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §5.4 / 规格书 G4：原文直引覆盖率 <0.60 阻断回录入；只能"追加式修改"，不能删 AI 抽取项。
- 三色标注即"事实(正常) / AI 推断(紫) / 待确认(灰)"可视化——答辩可截此屏讲防幻觉。
- 画像确认和关键问题在同一屏连续展示，不再要求患者先点击“画像无误”才能看到问题。

**回答后的分析进度**：回答提交后进入第三阶段，统一进度卡固定在第三阶段顶部；就医方向可以先查看，路径、任务和专科参考意见等分析完成后再展开。

```
点【回答完毕】
  → 进入第三阶段，在页面顶部显示「正在整理你的就医建议」进度条
  → 按“整理资料 → 判断就医方向 → 整理相关科室建议”显示阶段状态和完成比例
  → 后台结果到达后自动更新画像、方向和专科参考意见
  → 进度完成后展开就医路径、任务和报告入口；部分失败时保留已生成内容并提供重新分析入口
```
- 设计理由：患者提交回答后能立即看到真实进度，路径和报告入口不会在分析完成前展示旧结果；后台处理期间有明确反馈，不会把等待误解为页面卡住。

### P5 屏：关键问题（阶段 2 内直接展示）
```
┌────────────────────────────────────────────────────────┐
│ 第五步 · 还差几个关键信息 (最多 3 个, 可跳过)              │
│ ┌────────────────────────────────────────────────┐      │
│ │ Q1 血糖最近控制得怎么样？                         │      │
│ │    为什么问: 影响内分泌科判断与视网膜评估           │      │
│ │    [空腹血糖约7.8] [不清楚/跳过]                   │      │
│ ├────────────────────────────────────────────────┤      │
│ │ Q2 做过眼底检查吗？                              │      │
│ │    为什么问: 视物模糊需排除糖尿病视网膜病变         │      │
│ │    [做过(可补结果)] [没做过] [不清楚]              │      │
│ └────────────────────────────────────────────────┘      │
│ 小字: 跳过会导致结果可靠性降低, 但不会编造你的情况          │
│                                [回答完毕, 生成分析 →]     │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §5.5：每题显示"为什么问 / 影响哪些判断 / 可答不知道 / 可跳过"。
- 问题卡紧接画像卡展示；点击回答后进入第三阶段，由顶部进度卡承接后台分诊和多学科整理。

### P6 屏：建议的就医方向
```
┌────────────────────────────────────────────────────────┐
│ 建议的就医方向                                           │
│ ┌─ 建议先看 ─────────────────────────────────────────┐   │
│ │ 🏥 内分泌科                                         │   │
│ ├─ 可能还需要一起看的科室 ──────────────────────────┤   │
│ │   肾内科　眼科                                     │   │
│ ├───────────────────────────────────────────────────┤   │
│ │ 这次可能需要多个科室一起评估，具体以线下医生判断为准。 │   │
│ └───────────────────────────────────────────────────┘   │
│ 注：牵头方向 ≠ 最终诊断科室，仅用于准备就医。             │
└────────────────────────────────────────────────────────┘
```
- 患者只看到建议先看的科室和可能协同的科室，不展示规则命中、模型受限发言、可靠性、病例类型或内部校验过程。
- 页面保留“牵头方向 ≠ 最终诊断科室”的提醒，避免把分诊方向误解为诊断结论。

### P7 屏：就医路径与每一步要做的事
```
┌────────────────────────────────────────────────────────┐
│ 就医路径与每一步要做的事                                  │
│ ① 先整理资料                                             │
│    路径中的任务：整理近 3 个月血糖记录　[标记完成]          │
│ ② 挂内分泌科咨询                                         │
│    路径中的任务：带上已有检查结果　[标记完成]              │
│ ③ 根据检查结果再决定下一步                               │
│    路径中的任务：就诊后补充新检查或方案　[稍后处理]         │
│ ⚠ 本路径为建议，以线下医生判断为准                         │
└────────────────────────────────────────────────────────┘
```
- 路径和任务放在同一栏，任务紧跟产生它的路径步骤，患者能直接看出“现在做什么、做完后去哪一步”。
- 任务仍保留完成、稍后处理等状态操作；优先级使用“重要/常规/可选”，不展示内部任务来源和规则键。
- 涉及医疗判断的任务使用“带资料就诊”“向医生确认”等提示，不替患者下诊断或治疗指令。

### P8 屏：AI 多学科参考意见（患者摘要）
> 设计原则：逐科发言、共识分歧、证据追溯是给医生看的过程，不是给患者看的内容。患者端只展示每个相关科室主要关注什么、下一步准备什么。

```
┌────────────────────────────────────────────────────────┐
│ AI 多学科参考意见                                       │
│ 相关科室根据你提供的资料整理了下面的参考提示：             │
│ ┌─ 内分泌科 ─────────────────────────────────────────┐  │
│ │ 这个科室主要关注：血糖控制和相关检查                   │  │
│ │ 参考提示：带上近期血糖记录和检查结果，方便医生判断。   │  │
│ ├─ 肾内科 ───────────────────────────────────────────┤  │
│ │ 这个科室主要关注：尿蛋白和肾功能                       │  │
│ │ 参考提示：就诊时带上已有尿检、肾功能结果。             │  │
│ └───────────────────────────────────────────────────┘  │
│ ⚠ 以上是 AI 参考提示，不是医生诊断；以线下医生意见为准。 │
└────────────────────────────────────────────────────────┘
```
- 对患者只保留“科室主要关注什么”和通俗、准确的参考提示；隐藏建议向医生确认、还不确定的部分、共识/分歧、置信度和内部质询等技术字段。
- 专科意见仍按科室分卡展示，避免把不同科室的意见强行合并成一个诊断结论；完整过程和结构化证据保留在医生端。
- 第三阶段的方向、路径任务和专科参考意见在同一页连续展示，不再通过“查看就医路径”或“查看 AI 多学科分析”按钮分段跳转；进度未完成时只显示顶部整理状态和已确定的就医方向，完成后才展开路径、任务和报告入口。
- 第三阶段只在页面底部保留两个统一操作：返回“核对资料”或进入“就医摘要”；方向、路径和专科意见卡片内部不再放返回按钮。
### P9 屏：一页就医摘要与患者就医准备单（核心交付物，适合带去线下）
```
┌────────────────────────────────────────────────────────┐
│ 一页就医摘要                       角标: AI辅助·尚未医生审核   │
│ 主要问题: 糖尿病5年+蛋白尿+视物模糊, 需明确管理路径          │
│ 关键资料: 尿蛋白++ / 二甲双胍0.5g bid / 血糖控制不详        │
│ 信息缺口: 血糖水平 / 眼底检查                              │
│ 建议咨询方向: 内分泌科优先(牵头), 协同 肾内/眼科            │
│ 建议向医生确认: ①血糖控制目标 ②二甲双胍剂量 ③眼底检查必要性  │
│ 当前任务: 3 项(见P7)                                     │
│ [打印就医准备单/导出PDF]  [查看完整报告 →]                 │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §12.1（报告体系·患者版）：禁止把未审核推断写成确定诊断/治疗意见。
- 打印按钮输出独立的“患者就医准备单”（控制在 1–2 页）：主要问题、建议先咨询的方向、就医步骤、当前待办、就诊时可问医生的问题、信息缺口和关键资料。
- 已发布的医生最终建议在页面顶部直接展示并进入打印报告；就医详情按需展开。未发布的意见不作为最终结果展示。

**完整报告视图：逐段折叠（2026-09-15 实现口径）**
```
┌ 完整报告 ─────────────────────────────────────────────────────────┐
│ 共 13 段，结构完整性：✅ 完整                    [展开全部]          │
│ ┌─ 目录（左）──────┬─ 正文（右，逐段折叠）───────────────────────┐ │
│ │ 1. 病例概况      │ 1 病例概况            一句话…        ▸      │ │
│ │ 2. 关键资料      │ 2 关键资料                    4 条    ▾      │ │
│ │ 3. 信息缺口      │   ┌──────────────────────────────────┐      │ │
│ │ …（滚动自动高亮）│   │ （展开后才显示这一段的内容）      │      │ │
│ │ 13. 审核记录     │   └──────────────────────────────────┘      │ │
│ │                  │ 3 就医方向                    2 项    ▸      │ │
│ └──────────────────┴───────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```
- 为什么折叠：13 段全展开是一屏滚不到底的"文档墙"，患者根本不知道哪段与自己有关；
  折叠后**标题 + 内容量提示（"4 条"/"2 项"/"空"）** 一目了然，需要哪段点哪段。
- 三个必须的联动（否则折叠会变成"藏内容"）：
  ① **点左侧目录会自动展开对应段落再滚过去**（不然只会跳到一个收起的标题上）；
  ② **打印/导出 PDF 前自动全部展开**，打印完恢复用户原来的折叠状态 —— 纸面上永远是完整报告；
  ③ 折叠状态在同一个病例内记住（切换"一页摘要/完整报告"Tab 不丢），但折叠**只影响显示**：
  收起时正文仍在页面里（复制、检索、无障碍读屏都拿得到）。
- 段落编号与目录编号一致（`1. 病例概况` ↔ `#sec-0`），键盘可直接 `Tab` 到段落标题按回车展开。

### 第四阶段：医生审核结果

- 未发布：显示医生尚未发布最终建议，下方准备资料保持明确的 AI 待审核状态。
- 已发布：首要展示医生最终建议、发布医生、时间和报告版本，保留报告查看、刷新、打印与我的病历入口。
- 读取失败：显示重试提示，不将获取失败当成没有医生建议；已有结果保留为上次读取的版本。
- 患者末页提供结果阅读，不承担医生意见录入；后端既有资料更新和历史数据继续保留。

## 4. 患者端关键状态与合规规则

| 规则 | 说明 |
|---|---|
| 画像门禁 | 原文直引覆盖率 <0.60 阻断进入分析（规格书 G4），提示补录 |
| 急症拦截 | 若文本命中危象词表（胸痛大汗等）→ 红色警示页"疑似急症请立即就医/拨打120"，不进入分析（G1） |
| PII | 提交后由后台自动完成脱敏与 PII 拦截；患者端不单独展示技术预览（G3） |
| 未审核标注 | 所有未过医生审核的分析结果带"AI 辅助分析 · 尚未经医生审核" |
| 不伪装完整 | 跳过追问 → 可靠性降级并在摘要中标注缺口，不编造 |
| 免责 | 摘要/报告固定段"本系统不能做什么"（急诊/儿科急症/精神危机/处方剂量等） |

## 5. 演示走查脚本（患者端，3-4 分钟，对应规格书 §2）

1. **注册/登录+目标**（20s）：患者首次可在患者端注册账号并自动进入流程；已有账号直接登录，再选择"不知道先看哪个科"（或展开选"多种老毛病"）。
2. **录入+脱敏**（30s）：粘贴一段出院小结 → 展示 PII 自动打码（口播：隐私合规）。
3. **画像确认**（30s）：逐条核对 + hover 指出处，口播"先对齐事实再让 AI 分析"。
4. **追问**（15s）：3 个高价值问题，答 2 个跳 1 个（展示缺口不编造）。
5. **分诊+科室确认**（25s）：先看系统建议的主责科室，患者可以确认或调整；提交后明确提示“仅该科室医生可见”。
6. **分诊+路径+任务**（40s）：进入合并后的就医路径，每一步下方直接显示对应任务，口播"把建议变成下一步行动"。
7. **AI 多学科参考意见**（25s）：等待动画 → 各科通俗参考卡出现，口播"系统按内分泌/肾内/眼科分别整理关注重点，结论与准备事项看这里"（过程细节到医生端再讲）。
8. **一页摘要**（20s）：滚动摘要 + 打印为 PDF。
9. **医生结果闭环**（30s）：医生完成必审项目并填写最终建议 → 发布审核版本 → 患者刷新第四阶段，查看建议、发布医生、时间及版本，并打印报告。
10. 合规转场全程可见（AI 辅助标注 → 若医生已审核则出现审核版对照）。

> 患者端 + 医生端两段录屏合起来 = 比赛演示视频完整 P0 叙事。**分工建议**：患者端讲"就医前决策辅助"（整理→分诊→任务→摘要）；医生端讲"MDT 分析审阅 + 医生把关 + 线下意见对照"，避免同一内容在两段重复。

## 6. 已定方案记录（原"待确认清单"，按建议定案）

### 患者端附加入口：我的病历

“我的病历”位于左侧流程导航下方，不作为第五个主流程阶段。病例列表只显示当前患者自己的安全摘要：病例编号、主要问题、最近更新时间、主责方向、处理状态和报告版本。每条病例提供“打开病例”和“历史记录”两个入口：“打开病例”进入四步工作区，回看资料、建议和医生结果；“历史记录”只回看提交、补充资料和报告发布的时间线。

病例列表默认每页显示 10 条，提供上一页/下一页和总数提示，避免历史病例堆叠在一屏内。病例标题统一使用“病例 #病例编号 · 主要问题”格式，保证患者能通过编号准确区分同类问题。历史页不重复展示首次病历正文或当前结构化摘要。时间线按时间顺序展示首次提交、各次补充资料和已发布报告；每个报告版本提供“查看此版本”，展示保存时的患者摘要、医生最终建议和可展开的就医详情。历史报告独立于当前工作区，不改变当前病例或报告；未保存正文、没有报告版本或请求失败时明确提示，不使用当前资料重建历史。历史版本接口只允许患者读取自己的病例，排除医生内部审核记录和指标。

患者端不展示医生内部审核操作、审核人账号、AI 内部推理过程或未发布的协同讨论；医生审核版只有在发布后才通过患者版报告入口展示。
