# 患者端 UI 设计说明（比赛版 v-competition）

> 配套：《产品开发规格书-比赛版v-competition.md》（本文是它的 §2 P0 演示链路 + §5 schema 的界面层展开）
> 形态：本地 Web 应用（浏览器界面）；**本文只描述设计，不包含任何实现代码**。
> 范围：患者端主流程 = **登录选角色 → 简单目标确认 → 资料录入 → 脱敏预览 → 画像确认 → 智能追问 → 分诊结果 → 就医路径与任务 → AI 多学科分析结果摘要 → 一页就医摘要 → 就诊后新资料更新 → 变化摘要**（对应规格书 §2）。
> 风格：与医生端 UI 说明共用一套 **冷静专业医疗风** token（见《UI设计说明-医生端审核台.md》§1，本文直接沿用：主蓝 `#1B5E8A`、背景 `#F4F7FA`、语义色一致），患者端仅密度更松、文案更口语化、面向中老年用户大字化。
> 说明：**AI MDT 逐科发言/共识分歧等完整过程内容归属医生端**（见医生端 UI 说明"屏 E：MDT 会诊审阅台"）——患者只关心结论与下一步，患者端只展示**分析完成后的各科摘要卡**；"就诊后新资料更新"补充的是患者手上有的新资料，医生实际意见的录入在医生端完成。登录页（屏 0 角色选择）两稿共用，此处不再重复线框。

---

## 1. 患者端一句话体验

> 患者把散乱的病历"交给"系统 → 系统先把事实理清楚（画像卡）→ 问几个关键问题 → 告诉该看哪些科、先做什么 → 多学科 AI 分析完成，给出能带去线下的一页摘要；看完医生回来把**新的检查/用药/医嘱资料**补进来，系统说明"这次改变了什么"。

## 2. 患者端流程地图（对应规格书 §2 P0 链路）

```
[登录页·进入患者演示] ─▶ P1 就医目标(轻量,可跳过)
   ─▶ P2 资料录入(粘贴/表单) ─▶ P3 脱敏预览与来源标注
   ─▶ P4 画像确认(质量门禁) ─▶ P5 智能追问(≤1轮≤3问)
   ─▶ P6 分诊结果(牵头科+协同科+理由)
   ─▶ P7 就医路径 + 任务中心(Action Center)
   ─▶ P8 AI 多学科分析完成(各科摘要卡, 患者视角)
   ─▶ P9 一页就医摘要(可带去医院) + 完整报告入口
   ─▶ P10 就诊后 · 新资料更新(患者手上有的资料)
   ─▶ P11 变化摘要
```
> 说明：逐科发言/共识分歧/证据追溯等完整 MDT 内容属于**医生端**（医生端 UI"屏 E"），患者端 P8 只给结论摘要。

> 顶栏全程常驻：作品名（左）+ 当前进度步骤指示条（中，P1-P11 进度点）+ 身份条（`患者 · patient_demo` [退出]）+ 合规角标（右）。
> 合规元素与医生端一致：任何未过医生审核的分析都带 **"AI 辅助分析 · 尚未经医生审核"** 提示。

## 3. 逐屏设计说明

### P1 屏：就医目标（轻量确认，可跳过）
> 设计原则：**中老年患者不需要"整理需求""术前问题清单""MDT"这类词汇**。本屏只做两件事——① 给最普遍的场景一个默认主选项（"该怎么看病/先挂哪个科"）；② 把少数特殊场景用大白话收进可折叠"更多情况"，允许全部跳过（系统根据资料自动判断，让患者在 P4 画像确认时校正）。

```
┌────────────────────────────────────────────────────────┐
│ 第一步 · 你是哪种情况？（只用来帮你更快开始，选不准也没关系） │
│                                                         │
│ ┌──────────────────────────────────────────────────┐   │
│ │ 😕 我/家人身体不舒服，不知道先该看哪个科、怎么办     │   │
│ │    推荐选择：多数人都是这种情况                      │   │
│ └──────────────────────────────────────────────────┘   │
│  ▽ 我的情况更特殊一点（可不选）                          │
│    □ 有好几种老毛病，想一起理清楚                        │
│    □ 几个医生说法不太一样，想对比一下                    │
│    □ 要做手术/治疗，想提前把想问的问题准备好             │
│ 小字: 不选也可以，我们会根据你提供的资料自动判断          │
│                              [直接开始录入资料 →]        │
└────────────────────────────────────────────────────────┘
```
- 内部仍映射主文档 §5.1 目标与规格书行为类型 A-E，但**界面只讲人话**；术语不出现。
- 特殊场景选项展开后选中的目的：调整追问侧重点、任务排序与展示重点（如选了"手术/治疗"则在追问与任务里多提示术前评估项），**不直接决定分诊结论**（主文档 §5.1 红线）。
- 患者任何时候可从顶栏回到本页修改。

### P2 屏：资料录入（双 Tab）
```
┌────────────────────────────────────────────────────────┐
│ 第二步 · 把病情资料放进来                                │
│ [ Tab1: 粘贴病历 ]  [ Tab2: 表单填写 ]                   │
│ ┌────────────────────────────────────────────────┐      │
│ │ 粘贴门诊病历 / 出院记录 / 检查报告正文…            │      │
│ │ (≤8000字; 系统会先帮你整理成画像卡供确认)          │      │
│ └────────────────────────────────────────────────┘      │
│ 主要问题(选填): [________________________________]       │
│ ⚠ 请勿填写姓名/身份证/手机号/住址(系统将自动提示脱敏)       │
│                                [继续 → 脱敏预览]          │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §5.2；Tab2 表单 = 精简动态行（症状/既往史/用药/检查，均可加行），并在 Tab2 提供**既往病史快捷点选**（常见慢性病/手术史 chip：糖尿病、高血压、冠心病、脑卒中、慢阻肺、肿瘤史等——照顾中老年不擅长打字）。
- **既往病史获取的设计口径（面向"给医院用"的产品定位）**：
  - ✅ 比赛版（演示数据可得）：粘贴病历自动抽取既往史（进 P4 画像）+ Tab2 快捷点选 + 患者自述。
  - 🔜 **远期（需医院 HIS/区域健康档案授权对接，比赛版不做、不宣称）**：患者授权后，系统从院内系统自动带出既往疾病、手术史、用药史与近期检查——这属于主文档"能力边界"与规格书 P2"真实医院对接"项；在演示与答辩材料中**不得声称已实现**，只能作为"应用价值/展望"一句话（防"文档与实现不符"红线，见考古报告）。
- 校验：主诉与主要问题双空 → 阻断提示（规格书 G2）；长度/数值域校验；PII 提示。
- 底部常驻：知情同意一行小字"内容将发送至 AI 服务用于生成就医参考，不使用于训练，可随时删除"。

```
│ ┌────────────────────────────────────────────────┐      │
│ │ 原文:  患者 张** , 男, 58岁, 电话 138****1234     │      │
│ │       病历号 A0**12 , 住址 上海市**区**路**号     │      │
│ │       医保卡号 ******                            │      │
│ │       (已打码项: 姓名/手机/病历号/住址/医保 5 处)  │      │
│ └────────────────────────────────────────────────┘      │
│ ✓ 打码项黄色高亮, 悬停可看类别; [撤销某项打码?] 不提供(安全) │
│ 每份资料自动标注来源: 原始医学文档 / 检查结果 / 患者自述      │
│                              [确认脱敏并提交 →]            │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §5.3；打码项黄底标注 + 右侧说明"为什么打码"。
- 原则：脱敏不可逆（演示简化）；提交后进入 P4 画像确认。

### P4 屏：画像确认（质量门禁 ★"第一道闸"）
```
┌────────────────────────────────────────────────────────┐
│ 第四步 · 系统先把你的资料整理成画像，请核对                │
│ ┌─ 基础 ────────────────────────────────────────────┐   │
│ │ 男 58岁        来源 S-1:12 (hover 显示原文)         │   │
│ ├─ 主诉与症状 ─────────────────────────────────────┤   │
│ │ 视物模糊3月渐重 [原文记载]   下肢浮肿1周 [原文记载]   │   │
│ ├─ 已知疾病 ───────────────────────────────────────┤   │
│ │ 2型糖尿病5年, 控制情况不详 [AI推断·紫标]  ←待确认    │   │
│ ├─ 检查异常 ───────────────────────────────────────┤   │
│ │ 尿蛋白 ++ [原文记载]                               │   │
│ ├─ 用药 ───────────────────────────────────────────┤   │
│ │ 二甲双胍 0.5g bid [原文记载]                       │   │
│ └─ 信息缺口 ───────────────────────────────────────┘   │
│   ⚠ 血糖控制水平不详 · 未提供眼底检查(高价值缺口,将追问)   │
│ [有误? 补充/修正]          ✓ 画像无误 [开始分析 →]        │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §5.4 / 规格书 G4：原文直引覆盖率 <0.60 阻断回录入；只能"追加式修改"，不能删 AI 抽取项。
- 三色标注即"事实(正常) / AI 推断(紫) / 待确认(灰)"可视化——答辩可截此屏讲防幻觉。

### P5 屏：智能追问（≤1 轮 ≤3 问）
```
┌────────────────────────────────────────────────────────┐
│ 第五步 · 还差几个关键信息 (最多 3 个, 可跳过)              │
│ ┌────────────────────────────────────────────────┐      │
│ │ Q1 血糖最近控制得怎么样？                         │      │
│ │    为什么问: 影响内分泌科判断与视网膜评估           │      │
│ │    [空腹血糖约7.8] [不清楚/跳过]                   │      │
│ ├────────────────────────────────────────────────┤      │
│ │ Q2 做过眼底检查吗？                              │      │
│ │    为什么问: 视物模糊需排除糖尿病视网膜病变         │      │
│ │    [做过(可补结果)] [没做过] [不清楚]              │      │
│ └────────────────────────────────────────────────┘      │
│ 小字: 跳过会导致结果可靠性降低, 但不会编造你的情况          │
│                                [回答完毕, 生成分析 →]     │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §5.5：每题显示"为什么问 / 影响哪些判断 / 可答不知道 / 可跳过"。
- 回答后进入后台分诊（P6 需等待 2-5s，用进度骨架屏"正在分析科室方向…"）。

### P6 屏：分诊结果
```
┌────────────────────────────────────────────────────────┐
│ 分析结果 · 建议的就医方向                                │
│ ┌─ 建议优先咨询 ────────────────────────────────────┐   │
│ │ 🏥 内分泌科(牵头方向)     理由: 糖尿病5年血糖待控     │   │
│ │    依据: 规则命中 "糖尿病→内分泌(strong)" [展开]     │   │
│ ├─ 可协同咨询 ─────────────────────────────────────┤   │
│ │   肾内科(蛋白尿→肾病评估)   眼科(视物模糊→眼底)      │   │
│ ├─ 可靠性 ─────────────────────────────────────────┤   │
│ │   可靠性: 中 (血糖控制情况未确认) [原因]             │   │
│ └─ 是否需医生复核: 建议复核(复杂共病) ────────────────┘   │
│ 注: 牵头方向 ≠ 最终诊断; 仅就医信息组织的优先方向          │
│                    [查看就医路径与任务 →]                │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §7.1 / 规格书 `TriageResult`；规则信号可展开（技术感截屏点）。
- 可靠性等级旁永远带"原因"，遵守主文档 §6.5"每个等级必须显示原因"。

### P7 屏：就医路径 + 任务中心（Action Center）
```
┌────────────────────────────────────────────────────────┐
│ 就医路径(条件分支)       我的任务(3 项)                   │
│ ①先做资料准备 ──▶ ②挂内分泌科 │ ⬜ 整理血糖近3月记录(资料)  │
│    │(并行)            咨询       │  高优先级               │
│    ├─ 先查眼底检查 ──▶ ③带结果 │ ⬜ 向医生确认: 二甲双胍量  │
│    └─ 先查肾功能   复诊       │     是否需要调整(就医咨询) │
│ 后续路径取决于新检查结果       │ ⬜ 就诊后上传新检查/新方案    │
│ ⚠ 本路径为建议, 以线下医生为准 │     (就诊后更新)             │
│                              │ 每项: 优先级/原因/来源/可完成│
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §7.2/§7.3 / 规格书 `TaskItem`：任务含类型/优先级/原因/关联判断/状态。
- 医疗行为类任务文案必须是"建议向医生确认是否需要 ××"，禁止指令式（演示合规点）。

### P8 屏：AI 多学科分析完成 · 各科摘要卡（患者视角）
> 设计原则：**逐科发言、共识分歧、证据追溯是给医生看的过程，不是给患者看的内容**（完整内容在医生端"屏 E：MDT 会诊审阅台"）。患者端只在分析完成后展示"请了哪几个科室、各科主要建议"，重点是结论与下一步。

```
┌────────────────────────────────────────────────────────┐
│ AI 多学科分析已完成 · 请了 3 个科室一起看你的情况           │
│ (等待动画 ~5s: "正在请 内分泌科/肾内科/眼科 分析…")         │
│ ┌─ 分析完成 ─────────────────────────────────────────┐  │
│ │ 🏥 内分泌科   建议: 先完善血糖与肾功能评估再定方案      │  │
│ │ 🏥 肾内科     建议: 蛋白尿需评估, 看肾内科前先查肾功    │  │
│ │ 🏥 眼科       建议: 视物模糊需尽快查眼底               │  │
│ │ 共识: 都建议先完善血糖与眼底检查 [更多细节→医生可看]    │  │
│ └───────────────────────────────────────────────────┘  │
│ ⚠ 以上是 AI 分析视角, 不是医生诊断; 线下医生意见为准       │
│                    [查看就医路径与任务 →] 或 [查看摘要 →]   │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §8/§9 的**结果层**：只做"哪些科室参与 + 每科一句建议 + 有无共识/分歧提示"；证据板/分歧细节不在此展开（医生端可看）。
- 若专科间存在分歧：仅提示"几个科室看法不完全一致，需医生复核"，把"看细节"引导到医生端——对患者诚实但不制造焦虑。
- 演示口播点：这里承接 P6/P7，证明"系统真的做了多学科分析"，同时把"过程"留到医生端演示里讲，避免患者端视频冗长。

### P9 屏：一页就医摘要（核心交付物，适合带去线下）
```
┌────────────────────────────────────────────────────────┐
│ 一页就医摘要 (可打印/导出PDF)   角标: AI辅助·尚未医生审核   │
│ 主要问题: 糖尿病5年+蛋白尿+视物模糊, 需明确管理路径          │
│ 关键资料: 尿蛋白++ / 二甲双胍0.5g bid / 血糖控制不详        │
│ 信息缺口: 血糖水平 / 眼底检查                              │
│ 建议咨询方向: 内分泌科优先(牵头), 协同 肾内/眼科            │
│ 建议向医生确认: ①血糖控制目标 ②二甲双胍剂量 ③眼底检查必要性  │
│ 当前任务: 3 项(见P7)                                     │
│ [打印/导出]  [查看完整报告 →]                             │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §12.1（报告体系·患者版）：禁止把未审核推断写成确定诊断/治疗意见。
- 完整报告入口可看：专科意见卡 + 共识/分歧/不确定性 + 医生最终意见（若有审核版）。

### P10 屏：就诊后 · 新资料更新（患者补充手上有的新资料）
> 设计原则：**"医生实际意见"应由医生/医院系统记录，不该让患者回填**（真实场景中医生端或医院系统录入，比赛版由医生端"录入线下意见"完成，见医生端 UI 说明）。患者端这里只让患者补充**他自己手上有的东西**——看完病带回来的新检查、新处方、症状变化——这对患者是自然动作，不是额外义务。

```
┌────────────────────────────────────────────────────────┐
│ 看完医生了？把带回来的新资料放进来, 系统帮你更新建议        │
│ ┌────────────────────────────────────────────────┐      │
│ │ □ 新的检查/化验结果(拍照或文字)   [上传/粘贴]     │      │
│ │ □ 医生开的药/调整的方案(拍照或文字) [上传/粘贴]   │      │
│ │ □ 症状变化: [____________________]              │      │
│ │ □ 复查安排: 下次 [____] 到 [____] 复查           │      │
│ └────────────────────────────────────────────────┘      │
│ 来源标注: 你补充的内容标记为 [患者上传·待验证]             │
│ 医生实际意见: 由就诊医生/医院系统记录(见"医生审核台")       │
│                              [提交 → 查看变化摘要]         │
└────────────────────────────────────────────────────────┘
```
- 对应主文档 §14 / 规格书 §7 补资料回路：来源分级 = 患者上传（自述/文档）/ 医生上传 / 医院文档 / 未验证；**患者上传永不自动变成"医生确认意见"**。
- "AI 建议 vs 医生意见"对照：数据来自医生端录入的线下实际意见（比赛版演示由演示审核人在医生端执行），患者端 P11 只展示对照结果入口。
- 若患者没有新资料也可直接跳过本屏（就诊后闭环为可选增强，不阻塞主流程）。

## 4. 患者端关键状态与合规规则

| 规则 | 说明 |
|---|---|
| 画像门禁 | 原文直引覆盖率 <0.60 阻断进入分析（规格书 G4），提示补录 |
| 急症拦截 | 若文本命中危象词表（胸痛大汗等）→ 红色警示页"疑似急症请立即就医/拨打120"，不进入分析（G1） |
| PII | 提交前打码预览，命中即阻断分析（G3） |
| 未审核标注 | 所有未过医生审核的分析结果带"AI 辅助分析 · 尚未经医生审核" |
| 不伪装完整 | 跳过追问 → 可靠性降级并在摘要中标注缺口，不编造 |
| 免责 | 摘要/报告固定段"本系统不能做什么"（急诊/儿科急症/精神危机/处方剂量等） |

## 5. 演示走查脚本（患者端，3-4 分钟，对应规格书 §2）

1. **登录+目标**（15s）：登录页"进入患者演示" → 主选项"不知道先看哪个科"（或展开选"多种老毛病"）。
2. **录入+脱敏**（30s）：粘贴一段出院小结 → 展示 PII 自动打码（口播：隐私合规）。
3. **画像确认**（30s）：逐条核对 + hover 指出处，口播"先对齐事实再让 AI 分析"。
4. **追问**（15s）：3 个高价值问题，答 2 个跳 1 个（展示缺口不编造）。
5. **分诊+路径+任务**（40s）：牵头科+理由展开 → 任务列表，口播"把建议变成任务"。
6. **AI 多学科分析**（25s）：等待动画 → 各科摘要卡出现，口播"系统请了内分泌/肾内/眼科一起分析，结论与下一步看这里"（过程细节到医生端再讲）。
7. **一页摘要**（20s）：滚动摘要 + 打印为 PDF。
8. **就诊后更新+变化摘要**（30s）：患者补充新检查结果/用药变化 → 变化摘要，口播"新资料到底改变了什么"（医生实际意见的对照由医生端演示承接）。
9. 合规转场全程可见（AI 辅助标注 → 若医生已审核则出现审核版对照）。

> 患者端 + 医生端两段录屏合起来 = 比赛演示视频完整 P0 叙事。**分工建议**：患者端讲"就医前决策辅助"（整理→分诊→任务→摘要）；医生端讲"MDT 分析审阅 + 医生把关 + 线下意见对照"，避免同一内容在两段重复。
