# 医生端审核台 UI 设计说明（比赛版 v-competition）

> 配套：《产品开发规格书-比赛版v-competition.md》（本文是它的 §2/§3/§5/§10 的界面层展开）
> 形态：本地 Web 应用（浏览器界面）；**本文只描述设计，不包含任何实现代码**。
> 范围：**全局入口（登录页 + 角色选择）** + 医生端 = **演示级只读审核台**（内置账号、操作落库 SQLite）。
> 风格：**暖色编辑风（Claude 风）**——米白纸感底色 + 陶土主色 + 衬线标题，克制留白、信息密度适中，先"可信"后"好看"。
> 说明：登录页为患者端 / 医生端共用入口（对应主文档 §11、规格书 §3.1）；进入患者工作台后的主流程界面属患者端 UI，另行设计说明。本稿详述登录页与医生端审核台。
> **文档一致性说明（2026-09-17 修文档债）**：本稿早期版本写的是"医疗蓝 `#1B5E8A` / `#F4F7FA`"，
> 与实现的暖色 token 不符。**结论是实现正确、文档过时**——统一以 `static/css/tokens.css` 为准（下文 §1.2 已改正），
> 不回头改 CSS。判据：`tokens.css` 是唯一色彩来源，`dsh.css` 只 `@import` 它。

## 1. 设计总则与视觉规范

### 1.1 一句话体验
> 审核人打开一个病例，像"批改作业"一样逐条看 AI 的判断与证据，接受 / 修改 / 驳回，落一条清晰的记录；每一条操作都让观众看得见"人把了关"。

### 1.2 色彩规范（设计 token）

> 单一来源：`backend/static/css/tokens.css`（`dsh.css` 只 `@import` 它，不另立色值）。
> 下表是**实现中真实存在的 token**，改色只改 `tokens.css`。

| Token | 色值 | 用途 |
|---|---|---|
| 主色 Clay 陶土 | `--clay` `#d97757` | 主按钮、选中态、导航高亮、链接 |
| 主色 hover | `--clay-hover` `#c6613f` | 悬停、按下 |
| 主色 dark | `--clay-dark` `#c46849` | 深色底上的强调、描边 |
| 背景 纸感 | `--gray-050` `#faf9f5` / `--gray-100` `#f5f4ed` | 页面底色、次级面 |
| 卡片表面 | `--gray-000` `#fff` | 卡片 / 面板 / 弹层 |
| 分割线 | `--gray-200` `#e8e6dc` / `--gray-250` `#dedcd1` | 卡片描边、分隔 |
| 正文 Ink | `--gray-950` `#141413` / `--gray-800` `#262624` | 主要文字 |
| 次级文字 | `--gray-600` `#5e5d59` | 说明、次要信息 |
| 弱化文字 | `--gray-500` `#87867f` / `--gray-400` `#b0aea5` | 占位、禁用、角标底色 |
| 确认绿 | `--ok` `#2E7D4F` | "接受 / 已确认 / 有明确证据" |
| 警示琥珀 | `--warn` `#B7791F` | "暂不确定 / 间接证据 / 需复核" |
| 危险红 | `--danger` `#B3402E` | "驳回 / 危象 / 冲突 / 删除" |
| 信息紫 | `--info` `#5B4B8A` | "AI 推断"类中性标注（非好非坏） |
| 焦点环 | `--focus-ring` `#3898EC` | 键盘焦点可见性 |

- 全界面**色彩面积 <10%**：大面积保持白/米白，彩色只用于状态与操作，医疗场景不宜花。
- 危象 / 急症相关只用 Danger 红，且不得只靠颜色传达（必须配文字，见 1.6）。
- 语义色（ok/warn/danger/info）与"医疗蓝时代"的取值一致 —— 三色是合规语义色，不随主色切换而变。

### 1.3 字体与排版
- 中文字体栈：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`（跟随系统即可，比赛不引字体文件）。
- 数字/科室代码/时间：`font-variant-numeric: tabular-nums`（或等宽栈），保证表格对位整齐。
- 字号梯度：页面标题 20px / 卡片标题 15px(600) / 正文 14px / 辅助 12px / 角标与徽章 11px。
- 行高 1.6；正文不做两端对齐；中文不加斜体。

### 1.4 布局与间距
- 页面结构：**顶栏(病例上下文) + 左导航 + 主内容区**（宽屏再加右轨审核面板）。
  - **屏 A 例外（2026-09-17 队列优先改造）**：左导航**不再重复放病例列表**，只做「筛选 + 汇总」；
    病例以**单列队列表**占满主区。原因：列表曾经在两处各出现一次，且左轨写死 `slice(0,20)`，
    库里 221 例时医生**看不到第 21 例之后的病例**。
- 间距体系：4/8/12/16/24/32（px）；卡片内边距 16-20，卡片间距 16。
- 内容区最大宽度 ~1200px，居中；表格行高紧凑但可读（≥40px 行高）。
- 所有"AI 意见"区块用统一**淡色底 + 左侧竖条**（暖色 token：`--info` / `--accent`）区分"人写的 vs AI 写的"。

**响应式与打印约定（2026-09-15 实现口径，有分档回归测试守着）**：

| 宽度 | 布局 | 关键点 |
|---|---|---|
| ≥1440px | 三轨：左导航 + 主内容 + **右轨审核面板常驻** | 屏 F 里的主区发布镜像隐藏，避免同一操作在屏上出现两次 |
| 1100–1439px | 两轨：左导航 + 主内容 | 右轨收起 → **发布审核版 / 录入线下意见由屏 F 主区承接**（`#rev-publish-inline`） |
| ≤1099px | 单列堆叠（左导航变卡片置顶） | `#rev-body` / `#list-body` 单列 |
| ≤640px | 单列 + 页面内边距收窄到 16px | 顶栏病例号换行显示，不隐藏信息 |
| 打印 | 隐藏顶栏 / 轨道 / 操作条 | 报告折叠段自动全部展开，折叠控件与按钮不打印 |

> **硬约定（踩过坑）**：**右轨里的关键操作必须有主区镜像**。曾经 `<1440px` 时右轨被
> `display:none` 收起，而"发布/录入线下意见"只写在右轨里 → 1366×768 笔记本或投影窗口下
> 医生审完却发不出去。现在由 `tests/test_responsive_layout.py` 在 8 档宽度上守着。

### 1.5 核心组件清单
| 组件 | 设计要点 |
|---|---|
| 角色选择卡 | 登录页两栏大卡（患者演示 / 医生演示）：图标 + 主文案 + 该端能力小字 + 预置账号名；hover 上浮+主色描边 |
| 登录表单 | 账号 + 角色下拉（可选）+ 密码；错误提示用红条"账号或角色不符"；演示可留快捷按钮跳过 |
| 身份条 | 登录后顶栏常驻：`角色 · 账号（如 医生 · doctor）` + 右上[退出登录] |
| 队列行（屏 A 主形态） | 单列队列表一行 7 格：`病例号` / `主诉` / `风险` / `可靠性` / `分析状态` / `待处理数` / `更新时间`；整行可点进屏 B。风险格用 Pill 标 高/中/低 |
| 队列工具条 | 顶部队列栏：状态筛选 + 排序下拉 + [刷新] + [批量补齐分析] + 一行"共 N 例"说明；`风险 / 待审数 / 最近更新` 三种排序 |
| 筛选栏（左轨） | 7 类筛选按钮（冲突 / 证据缺口 / 可靠性低 / 分析失败 / 待医生处理 / 免审 / 待复核），每类带命中数；下方是汇总卡（医生已处理 / 免审自动处理 / 待审） |
| 状态标签 Pill | 圆角胶囊，彩底 10% 透明度 + 深色文字（见 1.2 语义色） |
| 决策条目卡 | 每条 = 一条可审核结论；头部含目标类型 + 状态；主体含结论/理由/证据引用；底部操作条 |
| 证据引用 Chip | `来源S-1:34` 小胶囊，hover 弹出原文浮层（source_ref 悬停） |
| 证据状态标 | direct 绿 / indirect 琥珀 / missing 灰 / conflict 红 / doctor_confirmed 深绿勾 / awaiting 虚线框 |
| 操作按钮组 | 主要：接受(主色实心)；次要：修改、驳回、暂不确定、请求补资料(描边)；危险：驳回(红描边) |
| 角标 | 页面/导出件常驻 **"AI 生成 · 尚未经医生审核"** 或确认后 **"已由 XX 审核"** |
| 差异对照 | 左右两栏 or 行内 diff：AI 原文（删除线）→ 医生修改后（绿底），附原因 |
| 条目分组折叠 | 三组 `<details>`：必审（展开）/ 已处理（折起）/ 免审（折起+原因）；组头给条数、风险提示与一句口径说明 |
| 批量接受预览卡 | 列出"将接受 N 条（标题+内容摘要+风险）"与"需逐条判断 M 条（标题+原因）"，确认按钮写明条数，可取消；**先预览再落库** |
| 批次撤销条 | 有生效批次时常驻一条"批次 B-xxx 仍生效 + [撤销本批次]"；撤销走弹窗填原因，说明"历史不删除" |
| 抽检说明行 | 免审组内的抽检结果标注"本次抽检"并高亮条目，附一行"抽检不改变状态、不计入医生处理" |
| 右轨抽屉 | 顶栏「审核面板」按钮在窄屏以浮层打开右轨（宽屏常驻，不需要抽屉） |
| 空态/加载态 | 空态给引导文案；AI 模块加载用骨架屏 + "专科分析中…"进度 |

### 1.6 通用合规元素（所有页面必带）
- 右上或页脚常驻：`AI 生成，尚未经医生审核`（灰底小字）；该病例已被审核确认后才换成绿色 `已审核`。
- 报告预览与导出件同样带角标与免责行（与规格书 §3.3 / §11 一致）。
- 危象提示（若出现）：红色警示条 + 明确文字"疑似急症，请立即就医"，不依赖图标颜色。

## 2. 信息架构（页面地图）

全局入口 + **队列入口 + 4 个工作区**（2026-09-17 收敛：原 7 屏按"医生脑子里的分区"合并成四区，子视图仍是原来的屏），
从"选角色 → 队列 → 逐条审核"：

```
[0] 登录页（角色选择）
   ├─ 进入患者端 ─▶ 患者工作台（见《UI设计说明-患者端.md》：录入/追问/任务/摘要/资料更新）
   └─ 进入医生工作台 ─▶ ① 审核队列（入口，单列队列表 + 左轨筛选，默认「待我处理 + 风险优先」）
                        └─ 点击病例 ─▶ ② 概览〔病例总览 | 分诊依据 S1→S3〕
                                       ③ 证据与推理〔证据板 | MDT 会诊审阅台 ★〕
                                       ④ 审核〔报告审核 ★ 逐条决策条目 + 发布 + 线下意见〕
                                       ⑤ 历史〔审核记录与版本〕
```

> 左轨只列五个入口（队列 + 四区），每个区下面挂子视图；当前所在大区在左轨高亮。
> 收起/展开的约定：**队列是入口而不是"区"**，所以它单独一项，不放进四区。
> 右轨（审核进度 / 发布 / 录入线下意见）在 ≥1440px 常驻；窄屏改为**抽屉**，
> 由顶栏「审核面板」按钮打开（`.rail-open` 浮层）—— 但**关键操作的主区镜像仍然保留**，
> 抽屉只是"随手看一眼进度"的宽屏替代品，不是窄屏的唯一入口（见 §1.4 硬约定）。
> 分工：**逐科发言/共识分歧等 MDT 过程内容（原屏 E）属医生端**；患者端只看到各科结论摘要（见患者端 P8）。

## 3. 逐屏设计说明

### 屏 0：登录页与角色选择（全局入口，主文档 §11 / 规格书 §3.1）

```
┌────────────────────────────────────────────────────────────┐
│  (居中卡片, 白底, 背景浅蓝灰)                                │
│                                                             │
│   🏥  多学科就医智助系统                                      │
│  AI 辅助就医信息整理与多学科决策协作平台                      │
│                                                             │
│  ┌──────────────────┐   ┌──────────────────┐               │
│  │  进入患者端      │   │  进入医生工作台      │              │
│  │  patient     │   │  doctor      │             │
│  │  整理资料 / 就医路径│   │ 病例审核 / 证据审阅│             │
│  │  任务中心 / 就诊后更新│  │ 报告确认 / 线下意见录入│          │
│  └──────────────────┘   └──────────────────┘               │
│                                                             │
│  或：输入预置账号登录           账号 [__________] 角色 [▾]    │
│      密码 [__________]   [登录]                               │
│  ⚠ 本系统为就医辅助演示，不提供诊断/处方；急症请立即就医。      │
└────────────────────────────────────────────────────────────┘
```
- 两种进入方式都保留：**角色卡片快捷入口**（一键演示，最优先展示）+ **账号/角色登录**（体现真实产品形态，后台仍按角色执行权限判断——不能只做前端跳转）。
- 角色卡视觉：左右两栏对等（患者蓝 / 医生深蓝绿），下方一行小字点明该端能力；悬停轻微上浮 + 主色描边。
- 患者角色文案强调"资料整理 + 就医任务 + 就诊后资料更新"，医生角色强调"审核 + 证据 + 报告确认 + 线下意见录入"——一眼区分两端职责。
- 顶栏登录后显示身份：如"医生 · doctor（演示审核人）"，右上角[退出登录]返回本页。
- 数据来源：预置账号表（规格书 §11 对应演示账号）；不接真实认证体系。
- 合规：登录前不能访问任何病例数据（前端路由守卫 + 后端权限双重校验）；登录页即放置免责与急症提示。

### 屏 A：审核队列（队列优先主屏，2026-09-17 定稿）
```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏: 多学科就医智助系统 · 医生审核台            [演示审核人-医学生]   │
├──────────────┬───────────────────────────────────────────────────────┤
│ 筛选（左轨）  │ 队列栏: [状态▾ 待医生处理] [排序▾ 风险优先] [刷新]      │
│ ● 待医生处理 9│         [批量补齐分析]      共 221 例 · 已载入 20 例     │
│ ○ 冲突      3├───────────────────────────────────────────────────────┤
│ ○ 证据缺口  7│ 病例        主诉                风险 可靠性 分析  待处理 更新│
│ ○ 可靠性低  5│ #C001 女58  视物模糊3月,下肢浮肿  [高] 中   就绪  ●9    09-17│
│ ○ 分析失败  0│ #C002 男61  反复发热2周           [中] 低   就绪  ●5    09-17│
│ ○ 免审     12│ #C004 女33  皮疹伴关节痛          [低] 高   部分  ●2    09-16│
│ ○ 待复核    2│ …（按排序键降序；整行可点，进屏 B）                      │
│ ─────────────│                                                       │
│ 汇总          │                    [ 加载更多（还有 201 例） ]          │
│ 医生已处理 34 │                                                       │
│ 免审自动 560  │                                                       │
│ 待审 9        │                                                       │
├──────────────┴───────────────────────────────────────────────────────┤
│ 合规条: AI 生成 · 尚未经医生审核                                        │
└──────────────────────────────────────────────────────────────────────┘
```
- **形态**：左轨只做「筛选 + 汇总」，主区是一条**单列队列表**（不是卡片流，也不是左右两处各一个列表）。
- **7 列**：`病例（号+性别年龄）` / `主诉` / `风险` / `可靠性` / `分析状态` / `待处理数` / `更新时间`。
  宽屏按上述比例分栏；≤1280px 时可靠性列并入病例格，只保留最关键的六项。
- **排序（3 种）**：`风险优先`（默认）/ `待审数最多` / `最近更新`。
  风险分是**排序用的聚合分**（冲突 > 证据缺口 > 可靠性低 > 待处理数量），不是临床风险预测，界面上只说"风险"不说概率。
- **筛选（7 类，每类带命中数）**：`待医生处理`（默认）/ `冲突` / `证据缺口` / `可靠性低` / `分析失败` / `免审` / `待复核`。
- **分页**：每页 20 条，底部「加载更多」；接口同时回传 `total / has_more`，不会再把库里的病例静默截断。
- **返回保留现场**：从屏 B 返回队列时，筛选条件、排序与滚动位置都恢复（`S.queue.scroll`）。
- 数据来源：规格书病例库 + `DoctorDecision` 聚合的待审计数；"待处理数"**只计必审且未处理**（口径见 §4.1）。
- 文案：行内给"1 句主诉 + 风险 + 可靠性 + 分析状态 + 待处理数"，审核人扫一眼能判断优先级。
- **分析状态徽章（2026-09-14 新增）**：每行同时显示该病例的多学科分析状态——
  `分析中`（琥珀）/ `分析就绪`（绿）/ `部分未完成`（红）/ `分析失败`（红）/ `未分析`（灰）。
  医生据此决定"现在能审"还是"等它跑完再审"，不必点进去猜。

- **批量补齐分析**：点一次会把"分析未完成"的病例排队进后台任务（每次最多 3 例，已在跑/已完成的自动跳过），
  请求立即返回，列表状态随后自动从 `分析中 → 分析就绪`；医生可以先做别的事，不阻塞操作。
  - **"部分未完成"也会被排进去**（2026-09-15 实现口径）：只要有一个科室没跑出意见卡，该例就算未完成，
    重排时只重跑多学科那一步，不会把已经好的画像/分诊结果重算一遍；
  - 后台任务"卡在分析中"超过 10 分钟（例如服务重启把线程丢了）视为已失效，允许重新排队。

## 4. 审核操作状态机（界面层可见规则）

```
每条决策条目:
  awaiting(待审) ─接受→ confirmed(绿勾)
       │  └─修改→ modified(展示 before/after, 绿勾+铅笔标) → confirmed
       ├─驳回→ rejected(红, 原因必填, 该条不进报告)
       ├─暂不确定→ uncertain(琥珀, 进"待医生确认问题清单")
       ├─(规则判定免审) → auto_processed(灰, "免审（自动）", **不计入待审、不算医生确认**)
       └─(批量接受后又撤销) → reopen(撤销, 原因必填) → **回到 awaiting 并升为必审**
任意资料更新 → 受影响条目回到 awaiting(保留医生原意见对比) → 重新审
全部【必审】条目终态后 → 报告可 [确认发布] → 顶栏角标 "已审核"
```
- 界面必须让观众随时看懂"当前这版是 AI 原稿还是医生已把关"——靠角标 + 条目状态色双保险。

### 4.1 发布闸门与"免审"口径（2026-09-17 实现，修过一个真缺陷）

| 概念 | 规则 |
|---|---|
| **必审条目** | `needs_doctor_review = true`（科室入选 / 共识分歧 / 患者建议；以及**要求医生决定**的路径步骤） |
| **免审条目** | 未要求医生决定的路径步骤 → 派生态 `auto_processed`，**不落库**；界面灰标"免审（自动）"并显示原因 |
| **待审计数** | 只统计"必审且未处理"的条目；免审条目**不计入待审红点** |
| **发布闸门** | 必审条目全部终态才能发布；**免审条目不会阻塞发布**（修复前它们会，实测占条目 21.9%） |
| **批量接受** | 「全部接受必审条目并发布」**只批量接受必审条目**，每条留审核记录；免审条目**不会被记成医生接受** |
| **审计口径** | 审计与报告分开写"医生处理 N 条 / 免审自动处理 M 条"，报告「审核记录与版本」新增一行"免审条目：M 条（未计入医生审核）" |
| **界面上看不到的** | 不出现"AI 自动审核/AI 决定"字样 —— 语义是**风险分级的自动处理**（规则判定），不是 AI 临床结论 |

> 红线：`auto_processed` 与"医生已接受"必须永远可区分（报告、审计、导出都不例外）。

### 4.2 队列口径（2026-09-17 实现，杀掉一个静默截断）

| 概念 | 规则 |
|---|---|
| **队列数据源** | `case_flow.list_review_cases(limit, offset, filter, sort, department, state)` → `{rows, total, has_more, scanned, scan_limit, filters, sorts}` |
| **列表上限** | 修复前：左轨 `slice(0,20)` + 后端 `list_review_cases(limit=100)` **双重截断** → 221 例只看得见 20 例。现在后端 `store.list_cases(limit, offset)` 真分页，前端"加载更多"每页 20 |
| **7 类筛选** | `doctor_pending`（默认）/ `conflict` / `gaps` / `low_reliability` / `analysis_failed` / `exempt` / `recheck` |
| **3 种排序** | `risk`（默认，风险分降序）/ `pending`（待审数降序）/ `updated`（更新时间倒序）；**排序键相同时按病例号做 tiebreaker**（修过"第二排序键吞掉 tiebreaker"） |
| **风险分** | `_case_risk()` 聚合：冲突 > 证据缺口 > 可靠性低 > 待处理数量；仅用于**排序与筛选**，不是临床风险预测，界面不出现概率 |
| **行内字段** | `risk_level` / `risk_rank` / `conflict_count` / `gap_count` / `exempt_items`（免审条目数） |
| **扫描上限** | `scan_limit=5000`：极端情况下只扫最近 5000 例做聚合，接口如实回传 `scanned`，不假装是全量 |
| **返回保留现场** | 筛选 + 排序 + 滚动位置存在前端 `S.queue`，从屏 B 返回时恢复 |

> 红线：**"看不到"和"没有"必须可区分** —— 队列必须能说出自己一共多少例、还有多少没载入。

### 4.3 分组折叠、批量接受与抽检（2026-09-17 实现，详情收敛）

实测平均 **25.6 条/例**（10–33 条）。全铺开时医生很难找到"真正要动手的那几条"，所以审核屏按风险分组：

| 分组 | 默认 | 内容 | 组内说明 |
|---|---|---|---|
| **必审待处理** | **展开** | 必审且未处理（`needs_doctor_review && awaiting`） | "这些条目需要医生逐条确认后才能发布审核版" |
| **医生已处理** | 折起 | 已有生效决策的条目 | "改判会再追加一条记录"（历史只增不删） |
| **免审（自动）** | 折起 | `auto_processed`（规则判定免审） | 组头直接显示免审原因；可**随机抽检**或直接接管 |

条目风险标（`risk_level`，**只用于"展开谁、能否批量"，不是临床风险预测、界面不出现概率**）：
`高` = 分歧待裁决 / 证据冲突 / 医生标了暂不确定；`中` = 其余必审；`低` = 免审。

**批量接受的三条硬规矩**（7.3 收紧，此前是"一键全部接受"）：

| 规矩 | 口径 |
|---|---|
| **限低风险** | 只作用于低风险必审条目（科室入选 / 患者建议 / 要求医生决定的路径步骤）。**分歧待裁决与证据冲突永不参与批量** —— 批量通道不能替医生裁决（红线） |
| **先预览** | `GET /batch/preview` 给出"将接受 N 条 + 被排除 M 条**及原因**"，只读不落库；预览与执行共用同一份判定，避免"预览 3 条、实际动 5 条" |
| **可撤销** | 每次批量有一个 `batch_id`；`POST /batch/undo` **追加**"撤销（回到待审）"记录（不删除历史）、**原因必填**；撤销后条目回到待审并**升为必审**；**已发布的病例不允许撤销**（否则报告版本与角标会打架，提示走患者端补资料触发复核） |

**抽检（免审 ≠ 没人看）**：免审组提供「随机抽检 3 条」，`POST /sample` 随机抽几条给医生过一眼。
抽检**只读**：不改条目状态、留一条审计（抽了哪几条可追溯）、**不计入"医生处理"**；
医生真的在这条上接受了，才计入医生处理与审核记录 —— 否则抽检就成了给免审条目偷偷盖医生章。

**计数自洽**：`医生已处理` 只统计"决策仍然生效（终态）"的条目。被整批撤销、已回到待审的条目
不能既算"待审"又算"医生已处理"（否则进度条会骗人）。

## 5. 演示走查脚本（3-4 分钟，对应规格书 §2 / §3）

1. **登录选角色**（15s）：打开系统 → 登录页出现，点"进入医生工作台"（doctor），口播"系统分患者/医生两个角色，医生进入审核台"。
2. **队列**（15s）：从审核队列（默认「待医生处理 + 风险优先」）点开 #C001，口播"医生先看风险最高的待审病例"。
3. **总览+依据**（35s）：画像卡 hover 指出处 → 切"分诊依据"展示 S1 规则信号，口播"每条推荐都有可展开的规则依据"。
4. **MDT 会诊审阅（50s）**：屏 E 三栏工作台 → "▶ 播放过程"顺序展开 独立研判→分歧出现→质询→各科补答，停在 1 条分歧/质询上，点"加入待确认问题"，口播"各科先独立判断、分歧如实呈现、AI 自己也会被质询——过程给医生看，患者只拿结论"（**全程无概率数字**）。
5. **逐条审核**（50s）：审核屏只有「必审待处理」是展开的 → 接受 2 条 → 修改 1 条（弹窗填原因）→ 驳回 1 条，口播"每条操作都留痕"；
   再点「批量接受低风险条目…」**先看预览**（将接受 N 条 / 需逐条判断 M 条及原因）→ 确认 → 点「撤销本批次」填原因撤回，口播"批量只覆盖低风险条目，分歧必须逐条判断，而且整批可撤销、撤销也留痕"。
6. **发布+版本**（20s）：确认发布 → 角标变绿 → 切审核记录页展示审计时间线收尾。
7. **就诊后对照**（30s）：患者线下就诊上传新资料后，医生端 [录入线下实际意见] → 展示"AI 建议 vs 医生意见"对照 + 变化摘要，口播"AI 和真实意见的差异也如实呈现"。
8. 全程顶栏与导出件可见"AI 生成·尚未经医生审核 → 已审核"的合规转场。

> 录屏素材可直接复用于比赛视频"登录 + 医生把关 + 就诊后对照"段；该段与患者端演示（从"进入患者端"开始录）合起来 = 完整 P0 叙事。分工建议：患者端讲"就医前决策辅助"、医生端讲"MDT 审阅 + 医生把关 + 对照闭环"，避免重复。
