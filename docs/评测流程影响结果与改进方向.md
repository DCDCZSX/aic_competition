## 3. 真实评测采集方案

### 3.1 参与者与病例

- 使用 20–30 例脱敏或合成病例，覆盖单科、共病、资料缺失和至少一例有分歧的病例；病例不带姓名、联系方式、身份证号或可逆病例号。
- 患者可用性任务由经过统一培训的参与者执行；医生工作量任务由符合项目要求的医学背景评审者或明确标注资质的评测者执行。
- 每个 `pair_id` 两种条件各完成一次；顺序随机，上一条件的页面状态和摘要清除。记录参与者培训版本和资质类别，不记录身份原文。

### 3.2 记录内容

- 患者：四阶段耗时和完成率、返回/错误次数、摘要查找正确数、可读性和“知道下一步做什么”评分。
- 医生：打开病例到完成必审项的耗时、必审条目数、实际决定数、修改/驳回、分歧处理、高风险条目复核和资料缺失往返及专科呈现覆盖。
- 失败、暂停超过协议时限、外部资料介入和重复观察按受控代码记录；不把缺失值填成 0。

### 3.3 报告方式

最终报告必须按患者/医生和人工/系统分别列出样本数、完成数、失败数和排除数；配对耗时差值只使用两侧均完成且没有协议偏离的病例。除非有足够的合格评审者和预先定义的评分表，否则不报告“质量提升”或医学结论。

## 4. 局限与后续

1. 当前 dry-run 记录是脚本夹具，不能回答患者是否更容易完成流程，也不能回答医生是否真实减少工作量。
2. 任务 9 仍缺真实人工配对数据、医学背景评审者和摘要可读性双盲评分；这些依赖团队安排，不能由仓库自动生成。
3. 即使真实流程耗时下降，也只能说明本测量条件下的工作量差异；不能外推到临床结局、诊断安全性或生产环境。
4. 采集完成后必须回填运行命令、数据来源、脱敏方式、参与者资质、分母、失败、排除和局限，并重新检查不得混入自由文本。
