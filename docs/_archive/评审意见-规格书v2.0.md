# 《AI 多学科就医辅助系统 · 最终版产品设计细则 v2.0》评审意见

> 评审对象：20 页 PDF。总体判断：方向正确、叙事完整，是"愿景文档"里的好版本；
> 但它离"可交付开发的规格书"还差两类东西：①被新功能挤掉的 v1.0 严谨件丢了；②新增模块缺机制定义。
> 按"先范围、后机制、再补件"排序。

---

## 一、🔴 范围：愿景 ≠ 比赛成品，必须显式分层（最优先）

### 1.1 §23 MVP 仍是大全集（患者 11 + AI Core 9 + 医生端 8 = 28 项）
- v1.0 评审已指出同类问题；v2.0 医生端反而**更重**（新增"AI vs 医生意见差异管理""请求补资料"）
- 全文仍无"几人 × 几周"的约束声明、无 P0/P1/P2、**无"演示核心链路"定义**
- 结果：开发时无从取舍，每项都"看起来必须做"，最后要么砍在答辩前，要么全做成半成品

**建议：**
1. 文档开头加"版本声明"：产品愿景（本文全部内容） vs **比赛成品（v-competition）**范围
2. 指定一条**演示核心链路**（P0，必须完整可用）：
   `目标选择 → 粘贴录入 → 画像确认 → 追问(≤1轮) → 分诊 → 路径 → AI MDT(3-4科) → 聚合 → 一页摘要+完整报告 → (演示)就诊结果回填 → 变化摘要`
3. 其余全部标 P1/P2，并给"3 人 × 3 周"口径下的人日粗估（沿用 v1.0 评审 22-26 人日的算法）

### 1.2 医生端的定位仍悬空（叙事负债未解决）
- 队伍无真实医生可用；§14-16、§22 却把医生端写成核心工作流
- **关键转机**：§20"就诊结果回填"是患者驱动的——**闭环其实不需要医生注册登录**：患者面诊后自己录入"医生实际意见"即可形成 AI vs 医生对照
**建议：** 把主闭环定义为"患者端 + 回填对照"，医生端降为"演示级只读审核台（用医学背景同学扮演验证）"；文档写清"医生端为概念演示，真实使用属后续验证计划"

## 三、🟠 新增模块缺"机制定义"（不定义就无法开发）

### 3.1 Action Center（§10、§16）——缺状态机与联动
- 未定义：任务状态（待办/进行/完成/延后/已回填）、任务来源规则（分诊路径步骤 ∪ 各科 high checks ∪ 医生请求）、"完成后下一步"的判定、完成任务是否触发增量重算
- **建议**：补 TaskItem schema + 任务状态机图 + "任务完成 → 触发局部重算 → 生成变化摘要"的回环

### 3.2 Evidence Board 的信息影响分析（§13.4）——缺依赖传播定义
- "补充某信息会影响哪些判断"必须有一张**依赖表**：画像字段 → 依赖它的专科/判断；没有它，这个功能就是空话
- **建议**：补"字段-专科依赖矩阵"（v1 手写、规则驱动，20-30 条核心映射即可）

### 3.3 共识/分歧/不确定性（§12、§13.3）——仍无判定机制与验收线
- 未定义：分歧 = 哪些科与哪些科的哪类字段冲突、怎么检测（建议：双高相关科室在 opinion/checks 上的方向性反义词表 + LLM 复核）
- **建议**：给机制 + 验收线（分歧检测精确率 ≥0.70，宁少勿多；抽样人工复核方法）

### 3.4 AI vs 医生差异管理（§15）——缺触发与呈现规则
- 冲突展示的条件是什么？任何不一致都展示，还是仅"就医顺序/科室/优先级"级别？冲突条目如何进"需要医生确认的问题"？
- **建议**：定义差异类型枚举（科室分歧/顺序分歧/优先级分歧/检查必要性分歧）与各自呈现模板

### 3.5 补资料回路（§16 ↔ §18）——缺状态机回路
- 医生请求补资料 → 患者补 → 重跑哪些模块 → 医生是否需重新审核？v2.0 §29（v1.0）的状态机被删，回路没定义

### 3.6 §21 数据留存与合规冲突
- 沉淀"医生最终意见/冲突/更新记录"意味着**长期留存结构化健康数据**——需明确：留存内容边界（原文仍不落盘？）、保存期限、患者删除权（删除后统计指标怎么办）、医生端访问控制

## 四、🟡 细节与一致

1. §0 的"10 步闭环"与 §25"核心体验"很好，建议配一张**真图**（当前全是 ASCII 箭头堆叠）
2. §8.3"是否需要 MDT"没有规则依据——建议补"类型→是否 MDT"决策表（对应 v1.0 §11 的 A-E 类型），一句话说清触发条件
3. 智能追问的"高价值信息"判断仍无定义：建议 = "缺失字段 ∈ 依赖矩阵中影响 ≥1 个专科判断的字段"（正好复用 3.2 的依赖表，一套机制两处受益）
4. 作品名"AI 多学科就医辅助系统"9 字可接受（≤20 字），但"一页摘要/完整报告"等章节宜配线框草图
5. 提示 v2.0 缺失了 v1.0 §20.2"演示模式必须标记'AI 生成，尚未经医生审核'"的合规细节——务必补回

## 五、保留亮点（别改丢）
- Action Center 把"给答案"变成"推过程"——这是产品气质升级的关键，方向正确
- §20 回填闭环把"无真实医生"短板转化为可演示的长期闭环，是最聪明的设计之一
- §13.4 自我设限"不做开放式医疗结果模拟"——安全边界意识好

## 六、建议修订顺序
1. §23 重排为 P0/P1/P2 + 指定演示核心链路 + 医生端降级（解决 1.1/1.2）
2. 补回 v1.0 六大严谨件（科室域/OOV/失败降级/无效输入/指标表/schema）
3. 给 Action Center、Evidence Board、分歧检测、差异管理补机制与依赖矩阵
4. 合规段补数据留存边界
