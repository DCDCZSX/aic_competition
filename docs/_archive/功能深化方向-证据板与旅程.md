# 功能深化方向：从"一次性分析器"到"有价值的软件"

> 背景：v1.0 规格书模块已经不少（画像/追问/分诊/路径/MDT/共识分歧/医生端/动态更新），
> 但用户感知仍是"把病例丢给 AI 收建议"。本文件诊断病根并给出方向菜单。

---

## 一、病根诊断：单一感来自"范式"，不是"数量"

现有产品 = **流水线型单次分析器**：
```
录入 → 画像 → 追问 → 分诊 → 会诊 → 聚合 → 报告  （执行一次，结束）
```
它缺四个"维度"，导致产品永远是"用完即走的工具"，而不是"有关系的服务"：

| 缺失维度 | 表现 | 现文档状态 |
|---|---|---|
| 时间维度 | 没有"前后对比/随访/变化"，病例是快照不是旅程 | 仅 §24 动态更新，且被列为大模块 |
| 探索维度 | 用户只能"收结论"，不能"看推理、质疑、试条件" | 完全没有（报告是纯文本） |
| 旅程维度 | 只覆盖"分析"，不覆盖"就诊前-中-后"的实操 | 只有"就诊前准备清单"一个点 |
| 资产维度 | 用户数据不沉淀，没有"我的档案/历史"，每用一次从零开始 | 仅历史记录被砍到 v1.1 |

## 二、三个修法框架（先想清往哪个方向长，再谈功能）

**A. 往"时间"长** —— 一次会诊 → 一段随访旅程
**B. 往"探索"长** —— 听结论 → 看证据、可质疑、可试问
**C. 往"旅程与资产"长** —— 单次工具 → 围绕就医全流程的档案与助手

下面每个方向都同时评估：对比赛的价值、成本、与现有引擎的复用度、演示效果。

---

## 三、方向菜单

### 方向 1：证据板（Evidence Board）—— 往"探索"长 ⭐ 首推
把"结论文本"升级为"可探索的证据空间"：
- 时间线视图：症状/检查/就诊事件按时间轴排布，异常值高亮
- 关联视图：每个专科判断 ↔ 支撑它的检查/症状（点"心外科判断"→ 显示依据哪条影像结论）
- **What-if 试问**："如果我补充了 XX 检查结果，分诊/会诊结论会怎么变？"（复用动态更新/局部重算引擎，只重算受影响模块）
- 分歧图谱：各科观点 + 依据 + 信息缺口的依赖关系网
- 价值：直接回答评委"你和直接把病历丢给 GPT 有什么区别"——GPT 给结论，你给**可审计的决策过程**
- 成本：中高（偏前端可视化 + 一个"增量重算"接口）；**核心引擎（局部重算）在 v1.0 §24 已有雏形，可复用**
- 演示：极强（交互操作比看报告出片得多）

### 方向 2：回访对照（AI vs 医生的"第二意见闭环"）—— 往"时间+资产"长
用户线下就诊后，把医生真实意见录入 → 系统生成"AI 建议 vs 医生意见"对照：
- 哪些一致（AI 可靠性证据）／哪些被医生修正（系统学习信号）
- 按科室统计"AI 建议被修正率" → 这就是"AI 建议接受率"指标的真实数据来源
- 叙事："不是一次性工具，是越用越校准的决策助手"
- 价值：把"没有真实医生"的短板变成"数据飞轮"的素材（哪怕先由医学同学扮演小样本）
- 成本：中（新增"回访录入 + 对照视图 + 统计"三个界面，无新引擎）
- 风险：真实回访数据难拿，1 个月内只能小样本/演示数据
- 演示：中上（对照表 + 修正率曲线有说服力）

### 方向 3：就医旅程三段态（就诊前 / 就诊中 / 就诊后）—— 往"旅程"长
把单次会诊包装成一次就医旅程的状态机：
- 就诊前：资料整理 + 分诊 + 路径 + 准备清单（现有能力）
- 就诊中：一键生成"给医生看的摘要页"（一页版已有）
- 就诊后：医嘱/新检查结果录入 → 增量更新（动态更新引擎）
- 价值：成本最低地改变"一次性"感知——同一套引擎，产品形态从"分析器"变"管理器"
- 成本：低-中（主要是状态管理与 UI 组织，几乎不写新 AI）
- 演示：中（流程感强）

### 方向 4：个人健康档案 + 多资料管理（往"资产"长）
用户跨多次就诊累积资料 → 系统成为"资料管家"：多份检查报告结构化入库、历史对比、导出给下一家医院。配合 OCR 导入（v1.1 项）。
- 价值：真实需求 + 留存场景；但**依赖长期使用与 OCR 管线，1 个月难成闭环**，风险高
- 成本：高；建议只做"档案列表 + 单病例回顾"，多病例对比留远期

### 方向 5：面向"代理/家属"的共享模式（往"关系"长）
复杂病例常由家属操作、多位家属 + 患者 + 未来医生多方查看同一档案：共享链接、谁补了什么资料的留痕、给家人看的"翻译版"（把报告转成人话+行动项）。
- 价值：人群真实（老年人就医场景强）；差异化足
- 成本：中（权限模型已有雏形 §32）；但真实使用验证难，同样依赖用户
- 演示：中

---

## 四、我的建议（结合 1 个月 + 无真实医生 + 要差异化 + 演示出片）

1. **主线签名功能 = 方向 1 证据板**（含 what-if 试问）。
   它不新增业务复杂度（复用画像/聚合/动态更新引擎），却把产品从"会诊报告生成器"提升为
   **"可审阅、可质疑、可试问的 AI 多学科决策支持台"**——这正是 §36 差异化叙事的最强落地，
   也是答辩时最不容易被"套壳"质疑的部分。
2. **结构层 = 方向 3 旅程三段态**，作为 UI 组织方式并入任何选择（低成本、立即改变"一次性"感知）。
3. **叙事预备 = 方向 2 回访对照**：功能不进 MVP，但"修正率/接受率"作为**远期指标**写进文档，
   答辩说"下一阶段"——给评委留想象空间。
4. 方向 4/5 明确列为"暂不做"，防止范围再次爆炸（与上轮评审一致）。

## 五、落地切法（避免范围爆炸）
- 证据板 v1 只做三块：时间线 + 判断↔依据关联 + **分诊级 what-if**（补一个字段重算分诊，不重算整个会诊）
- what-if 背后的"局部重算"与 §24 动态更新共用同一接口 → 一次开发两处受益
- 全量会诊级 what-if 列 v1.1（算力与时长不允许在 MVP 做）
