## 1. 产品定位与范围边界

### 1.1 定位（通用版，不含任何病种）
面向**症状复杂或多种疾病并存、难以自行判断就医路径**的人群，
AI 先帮用户明确"该看哪些科、是否值得多学科咨询"，再组织各专科协同分析，
输出可携带就医的结构化参考报告。红线：**就医决策辅助，不出诊断与处方**。

### 1.2 产品必须覆盖的 5 类行为（验收按此表，不按单一病种）
| 类型 | 通用触发条件 | 行为 | 跨病种示例（仅作验证用例，不是设计依据） |
|---|---|---|---|
| A 简单单科 | 单系统、无共病、无手术/危象信号 | 单科就诊建议，不触发会诊 | 急性上感发热咳嗽 3 天 |
| B 多病共病 | 已确诊慢性病≥2 且有跨系统症状 | MDT：主诊科室牵头 | 2 型糖尿病 5 年 + 蛋白尿 + 视物模糊 |
| C 疑难血液/系统病 | 血象异常/发热查因/诊断不明 | MDT 多科排查 | 发热 3 周 + 三系减少（噬血待排） |
| D 手术/介入决策 | 含术式/介入/围术期决策词 | MDT：外科牵头 + 麻醉/影像/内科评估 | 房间隔缺损修补 + 房颤射频消融术式 |
| E 危象/不可用输入 | §3.4 危象词表 / 非医学输入 | **拒绝出报告**，转 120/急诊或礼貌拒绝 | 持续胸痛伴大汗 |

### 1.3 非目标场景（写入"能力边界"一节，主动声明）
急诊抢救、儿科急症、精神危机干预、处方与用药剂量建议、美容/体检报告解读、慢病长期管理随访。声明边界 = 答辩防问。

## 2. 科室域定义 v1（替代"36 科限制"的未定义假设）

### 2.1 归类原则
1. 以"能独立对 MDT 议题给出意见的临床单元"为粒度（≈医院会诊常用科室名）
2. 二级亚专科并组：心衰/心律失常见心血管内科；不单设
3. 辅助诊断科（影像/病理/检验/超声/介入）保留为**可参与科**，但**不得担任牵头科室**
4. 牵头科室仅限临床科；`primary_route[0]` 由临床科担任
5. 出现频次高的独立科（超声科、介入科、肝胆外科）允许单列——真实 MDT 金标准中已出现

### 2.2 v1 科室全集
- 临床内科(13)：心血管内科、神经内科、呼吸内科、消化内科、肾内科、内分泌科、血液科、风湿免疫科、感染科、肿瘤科、老年医学科、急诊科、重症医学科
- 外科系(8)：普通外科、肝胆外科、骨科、神经外科、心胸外科、泌尿外科、血管外科、整形外科
- 临床专科(10)：皮肤科、眼科、耳鼻喉科、精神科、康复医学科、妇产科、儿科、新生儿科、中医科、针灸科
- 辅助科(6)：影像科、超声科、病理科、检验科、介入科、麻醉科

> 合计 37 门类；**以代码字典 `SPECIALISTS` 为唯一权威源**。本文不承诺"永远 37"，只承诺"全集=代码字典，新增走评审并同步别名表与前端展示"。

### 2.3 别名/近义映射（医院写法 → 域内名，全量表存 `ALIAS_MAP`，评测与分诊共用）
心内科→心血管内科；呼吸科→呼吸内科；肾内→肾内科；血液科/血液内科→血液科；感染科/感染性疾病科→感染科；风湿科/免疫科→风湿免疫科；康复科→康复医学科；内分泌二区→内分泌科；耳鼻咽喉科→耳鼻喉科；神外→神经外科；ICU→重症医学科。

### 2.4 域外（OOV）处理策略（写死，不留洞）
- 分诊候选或金标准中出现域外科（如口腔颌面外科）→ 按序处理：①命中 `ALIAS_MAP` → ②命中"最近似科表"并提示"已按近似科 XX 处理" → ③无近似 → 记 `oov_log`，报告中该建议以"建议咨询 XX（未建模）"原样呈现，不静默丢弃
- 评测口径：指标分"域内指标"与"含 OOV 近似指标"两列报告（诚实）

## 3. 决策链架构：规则库 vs 模型（评审缺陷 1 的修复）

总原则：**能规则化就规则化；模型只在规则覆盖不到处介入；模型输出必须过规则校验器；该拒绝就拒绝。**
分诊是全系统决策链的代表，先讲透；画像抽取与分歧检测同构复用（§3.2）。

### 3.1 分诊决策流水线（三段式，每段可离线单测）
```
S1 规则引擎(确定性) ──► R = {科室: score_R, 触发信号}
S2 模型层(LLM)     ──► 输入含 S1 的 R 清单 ──► M = {科室: conf(0-1), reason}
S3 仲裁器(确定性)  ──► 融合/校验/拒绝 ──► 输出 + decision_path 标注
```

**S1 规则引擎（确定性）**
- 规则 = `(条件, 科室, 权重, 触发信号)`；权重：strong=3 / medium=2 / weak=1
- 条件来源：①结构化画像字段（共病数、多系统标记）②关键词/正则信号
- 行为类型 A-E 由 S1 判定：手术词表命中→D；危象词表命中→E 直接拒绝，不进 S2
- 输出 R 每科带 `score_R` 与命中的具体信号文本（可解释）

**S2 模型层（受限发言）**
- 上下文 = 画像 + 主要问题 + 科室域 + **S1 已选清单及理由**
- 指令："逐科说明 采纳/补充/反驳；反驳强规则命中必须给出医学依据；对自己新增的科自报 0-1 置信度"
- 模型看到规则后再发言，从源头降冲突；**模型不拥有移除 strong 规则命中的权力**

**S3 仲裁器（确定性，无模型参与）**
- 入选规则（decision list，非加权和）：
  - R 中 strong（score_R=3）→ **必选**，模型不可剔除
  - R 中 medium/weak → 入选；weak 标"可咨询"优先级
  - 仅 M 新增 → 当且仅当 `conf ≥ 0.65` 且通过校验器
  - 校验器：科室∈域表；总数 ≤6；D 型强制含外科牵头科+麻醉/影像之一；牵头位=临床科
- 冲突处理（不静默）：M 明确反驳 strong 命中 → 保留该科 + 记 `conflict_log`，报告分歧区如实呈现
- 排序（仅 UI 用）：强规则 > 模型 conf≥0.8 > 中规则 > 弱规则/conf≥0.65
- 每病例记 `decision_path ∈ {rule-dominant, model-dominant, mixed, refused, degraded}`

### 3.2 画像抽取与分歧检测的分工（同构）
- 画像抽取：结构化字段（年龄/性别/数值/日期）走确定性模板解析；自由语义走模型；模型输出过"字段校验器"（类型/枚举/必填非空/source_ref 存在性）；`confidence=high` 仅当命中原文引用
- 分歧检测 v0：纯规则——对"双高相关科室"的 `checks[]` 与结论做方向性词表比对（如"建议手术 vs 保守观察"反义对），不做语义级判断；宁少报不误报（验收线 §5）

### 3.3 打分口径（避免伪精度）
- 不搞入选加权和；只保留三类量：规则权重分（S1）、模型自报置信（S2）、校验器布尔（S3）
- 任何分数不出现在用户可见 UI；用户只见理由与优先级标签

### 3.4 拒绝输出（guardrail）表
| ID | 触发 | 动作 |
|---|---|---|
| G1 | 危象词表命中（内置 ≥40 条可审计清单：持续胸痛伴大汗/意识障碍/大出血/严重呼吸困难/板状腹/自杀伤人/中毒；含"胸痛+大汗"类组合规则） | 阻断：显示"疑似急症，请立即拨打 120 或前往急诊"，不进入会诊、不生成报告 |
| G2 | 主诉与主要问题双空 | 阻断，引导补录 |
| G3 | 输入命中 PII（18 位身份证/11 位手机号等） | 阻断并提示清除（不做分析） |
| G4 | 画像校验失败：主诉未抽取 或 原文直引覆盖率 <0.60 | 阻断回第 2 步，提示确认/改表单 |
| G5 | 模型连续 3 次失败 且 规则零命中 | 降级：输出固定就医建议模板，不生成 AI 报告 |
| G6 | 非医学内容（闲聊/广告/试题） | 礼貌拒绝并说明用途 |

> G1 词表按"词→理由"集中维护并附审计清单（技术方案附录可查），这是答辩"安全设计"的实据。

## 4. 五步流程（v0.1 基础上的修订）

### 第 1 步：录入 🔴
- 双模式 Tab：A 粘贴正文（≤8000 字）；B 精简表单（必填仅 5 项：年龄/性别/主诉+时长/主要问题；既往史/检查/用药为动态行选填）
- 校验：G2、G3、长度与数值域；敏感信息提示（勿填姓名/身份证/手机号/住址）
- 提交后先进第 2 步画像确认（流程与 v0.1 相同）

### 第 2 步：画像卡确认 🔴（质量门禁）
- 呈现：分组卡 + 每条 `source_ref`（hover 出处）+ `confidence` 灰显推断项 + 信息缺口区（high 缺口可阻断；普通缺口放行但随行标注）
- AI 侧：模板解析 + 模型 + 字段校验器；**通过 G4 才允许"开始分析"**
- 用户操作：确认 / 补录缺口 / 仅允许"追加式编辑"（不删 AI 抽取项，减交互复杂度）

### 第 3 步：分诊与触发 🔴（走 §3.1 三段式）
- 输出：行为类型(A-E) + 就诊方向（优先级+理由）+ MDT 与否
- E 型→拒绝页；A 型→单科建议页（附"为何不需 MDT"一句）；B/C/D→会诊入口（科室只读，v1 不做手动编辑）
- 页面常驻合规条

### 第 4 步：会诊直播 🔴（简化版）
- 状态机：开场 → 逐科发言（读画像→分析→结构化意见卡）→ 分歧检测 → 协调生成
- **v1 砍跨科转诊二轮发言**：A 科意见卡含 `referral` 字段但**不触发 B 科补充轮次**；referral 汇总进报告第四段（保留 80% 效果，省 50% 复杂度）；二轮转诊列 v1.1
- 意见卡结构同 v0.1：specialty/relevance/opinion/checks(带优先级)/gaps/referral
- 会议桌 UI：左画像摘要 / 中科室卡状态灯 / 下发言时间线；"技术细节"开关列 v1.1
- 健壮性：单科失败标红可重试不阻塞；单科超时 120s→重试 1 次→标"未完成"跳过；总时长上限 8min；**v1 不做刷新恢复**（内存会话，刷新提示重来）

### 第 5 步：报告 🔴（文本优先）
- 七段式同 v0.1；分歧区含 `conflict_log`（若有）
- 导出 v1 = 浏览器"打印为 PDF"（不引入 PDF 库）
- 报告头时间戳 + "AI 生成·仅供参考"角标 + 页脚免责
- "就诊前准备清单" = 各科 high 优先级 `checks` 去重聚合 + 固定模板项

## 5. 失败与质量阈值总表（评审缺陷 5 的修复）

## 6. 数据与合规设计（评审缺陷 3 的修复）

**原则**：数据最小化、默认本地、可删除、第三方明示。
| 项 | v1 设计 |
|---|---|
| 知情同意 | 首次使用弹窗明示：①用途=生成就医参考 ②病历文本将发送至第三方大模型 API ③不使用用户数据训练 ④可随时删除。确认后方可录入 |
| 存储 | 默认本地运行；病历**原文不落盘**（仅内存）；审计只存"脱敏画像 + 报告" |
| 保存期限 | 本地会话记录 ≤30 天自动清理；设置页"一键删除全部数据" |
| 脱敏边界 | 前端提示 + G3 PII 拦截（身份证/手机/姓名掩码）；对外材料只用改写病例 |
| 访问控制 | 本地 127.0.0.1；在线演示需：访问口令、关 debug、不暴露管理接口 |
| 真实数据 | MDT-5.csv 使用前确认来源授权与脱敏程度；技术方案注明来源与用途 |
| 能力边界 | 报告固定段"本系统不能做什么"（§1.3） |

## 8. 跨病种验收集（评审缺陷 2 的落地）
- A 简单病：急性上感 → 单科，无 MDT
- B 共病：2 型 DM + 蛋白尿 + 视物模糊 → 内分泌牵头 + 肾内 + 眼科
- C 疑难：发热查因 + 三系减少 → 血液牵头 + 风湿 + 感染
- D 手术：房间隔缺损术式 → 心胸外科牵头 + 麻醉 + 心超 + 内科评估
- E 危象：持续胸痛伴大汗 → 拒绝出报告

> 5 例全过 = "分诊行为验收通过"；评测集 n≥30 由公开数据 + 人工标科扩充。
