# 《AI 多学科就医咨询助手（MDT）》架构升级设计方案

> 目标：把"患者输入→判科室→各科诊断→汇总"的原型，升级为
> **「多智能体多学科会诊」架构**——各专科 Agent 围绕同一份"病例画像"协同分析，
> 支持跨专科触发、分歧检测、结构化会诊纪要，并内置合规与防幻觉层。
> 所有"自研部件"都要能在答辩时指着代码说"这是我们设计的"。
>
> 前置假设（看完原型代码后回填修正）：输入为单次就诊史文本；后端 Web 已有；
> 当前各科室由同一大模型换 prompt 扮演；输出为文本报告。

---

## 1. 一句话架构定位

> **不是"多个角色轮流回答再拼接"，而是"围绕同一病例画像的受控多学科协作"。**
> 病例事实只有一个来源（画像层）→ 分诊决定谁参会 → 主持人规划问题 →
> 各专科只答本科、越界必转 → 矛盾不掩盖、如实呈现 → 输出结构化会诊纪要。

## 2. 真实 MDT 流程对照（答辩"懂行"证明，先讲清楚我们改了什么）

| 真实医院 MDT | 我们的线上化 | 差异说明 |
|---|---|---|
| 由病例复杂度触发（肿瘤/多病共存/诊断不明） | 分诊引擎输出"复杂度标记"决定是否触发多科会诊 | 对齐真实会诊启动条件 |
| 各科专家共享同一份完整病历资料 | **共享同一份"结构化病例画像"** | 防"各科各说各话"的关键设计 |
| 主诊科室牵头，列讨论问题清单 | **主持人 Agent** 生成"会诊问题清单" | 对齐主持流程 |
| 意见冲突现场讨论消解 | 分歧检测：**矛盾如实呈现 + 建议线下复核** | 合规且诚实的边界 |
| 输出会诊记录 | 输出结构化"会诊纪要" | 对齐文档规范 |

**产品定位红线**：对患者输出的是"就医决策辅助 + 专科咨询参考"，**不是诊断结论**；涉及诊疗分歧一律引导线下就医。

## 3. 目标架构（分层图）

```
┌─────────────────────────────────────────────────────┐
│ 应用层：Web 前端（病情录入 / 会诊过程可视化 / 纪要展示） │
├─────────────────────────────────────────────────────┤
│ 编排层：【会诊编排器】（自研核心）                      │
│   主持人Agent → 专科Agent池 → 跨科触发 → 分歧检测 → 纪要 │
├─────────────────────────────────────────────────────┤
│ 决策层：【分诊决策引擎】（自研）→ 科室清单 + 会诊触发判断  │
├─────────────────────────────────────────────────────┤
│ 事实层：【病例画像】（自研抽取）→ 共享事实的唯一来源       │
│   症状时间线 / 现病史 / 既往史 / 检查检验 / 用药过敏       │
├─────────────────────────────────────────────────────┤
│ 模型层：LLM API（固定版本）+ 结构化 JSON 输出            │
├─────────────────────────────────────────────────────┤
│ 合规层：边界系统提示词 / 输出过滤器 / 免责声明 / 审计日志   │
└─────────────────────────────────────────────────────┘
```

## 4. 核心流程（状态机）

1. **输入**：患者自由文本（后续可加多轮追问补材料）
2. **画像抽取**：自由文本 → `病例画像.json`（见 §6）
3. **分诊**：画像 → `{主诉科室Top3, 复杂度标记, 建议参会科室[] + 理由[]}`
   - 复杂度标记为"高"（多系统受累/多病共存/诊断不明/肿瘤相关）才进入 MDT 流程；
   - 复杂度低 → 降级为单科咨询（产品也诚实，不是什么都硬凑 MDT）
4. **主持**：画像 + 参会科室 → `会诊问题清单[]`（每科要回答的具体问题）
5. **会诊**：逐科执行
   - 专科 Agent 只能读画像 + 分配给自己的问题；
   - 输出 `专科意见卡`：本科判断 + 建议 + **信息缺口[]** + 是否越界转诊；
   - **跨科触发**：某科建议中提及他科检查/症状（如肾内科→"建议查眼底"）→ 编排器自动把该信息并入眼科的问题上下文
6. **分歧检测**：重叠领域意见一致性检查 → `{一致点[], 分歧点[]}`
7. **纪要生成**：结构化报告（见 §7），附免责声明
8. **落盘审计**：全流程日志（评测、答辩截图、可信溯源）

## 5. 三个自研部件（创新叙事核心，对应评分"创新性20"）

| 部件 | 实现要点（答辩指着代码讲） | 评测联动 |
|---|---|---|
| **① 病例画像抽取器** | "医学本体词规则 + LLM 校正"双通道；只抽取文本中**实际存在**的信息并标注置信度，禁止脑补 → 这是全系统防幻觉的第一道闸 | 供实验三使用 |
| **② 分诊决策引擎** | 自建"症状-科室映射规则库"（公开指南/教材整理，初版几十条，评测驱动扩充）+ LLM 决策 + **每条输出可解释理由** | 实验一：与纯 LLM 分诊对比准确率 |
| **③ 会诊编排器** | 主持人问题规划、专科角色隔离、越界拒答转诊、**跨科信息传递规则**、分歧检测与如实呈现 | 实验三：单科 vs MDT 增量价值对比 |

> 答辩防"套壳"三连问的自答模板：
> - "模型是现成的" → 对，模型是组件；**自研的是这层的病例事实约束、跨科协作规则与决策引擎**；
> - "为什么不直接问一个通用大模型" → 通用模型没有病例事实层约束会幻觉，没有角色隔离会答串科，没有分歧检测会掩盖矛盾；
> - "和真 MDT 什么关系" → 对齐真实流程做了线上化再造（见 §2 表）。

## 6. 数据结构（`病例画像.json` 草案）

```json
{
  "case_id": "C001",
  "主诉": "...",
  "症状时间线": [{"症状": "乏力", "部位": null, "时长": "3个月", "演变": "加重"}],
  "现病史": "...",
  "既往史": [{"疾病": "2型糖尿病", "病程": "5年", "控制情况": "不详"}],
  "检查检验": [{"项目": "空腹血糖", "值": "9.2 mmol/L", "异常标记": true}],
  "用药": [{"药": "二甲双胍", "剂量": "0.5g bid"}],
  "过敏史": [],
  "信息缺口": ["血糖控制情况不详", "未提供眼底检查结果"]
}
```

## 7. 输出：结构化"会诊纪要"（模板）

```
一、病例摘要（画像自动生成）
二、建议就诊方向（分诊引擎，含理由）
三、专科意见卡（每科一张：判断/建议/信息缺口）
四、跨专科提示（会诊中发现的联动建议，如"肾内科提示查眼底"）
五、一致点 / 分歧点（分歧如实呈现，建议线下 MDT/专科复核）
六、待补充信息清单（去大医院前建议先做的检查，提高就诊效率）
七、免责声明（固定模板，所有页面与导出件必带）
```

## 8. 技术选型建议（默认；等考古完原型后按实际替换）

| 层 | 建议 | 备注 |
|---|---|---|
| 编排实现 | **轻量自研状态机 + 结构化 JSON 调用各 Agent**（不引重量级框架，自研叙事更硬）；若时间紧可参考 LangGraph 的 StateGraph 思想但自己实现 | 与评测脚本直接函数级对接 |
| 后端 | 沿用现有；无则 Python FastAPI | 与 AI 管线同语言 |
| LLM | 沿用现有模型；固定版本 + temperature=0 | 可复现 |
| 前端 | 沿用现有；会诊过程做成"逐步可视化"（每科意见逐条出现） | 演示效果好 |
| 存储 | SQLite + 本地文件（病例、纪要、审计日志） | 免运维 |

## 9. 从原型到目标的升级路线（1 个月，按优先级）

| 阶段 | 内容 | 验收门禁 |
|---|---|---|
| Day 1-3 | 考古完代码 → 把现有流程映射进本架构 → 先补**合规层 + 报告结构化**（改动小、收益大） | 输出已含免责声明 + 结构化纪要字段 |
| Day 3-7 | **病例画像抽取器**落地（新模块）；日志/审计落盘 | 一份真实病例文本 → 画像 JSON 人工复核可接受 |
| Week 2 | **分诊引擎规则库 v0** + 主持人 Agent + 专科角色隔离改造（删掉"一个模型串讲"） | 实验一（分诊 Top-3 命中）跑通并过门禁 |
| Week 3 | **跨科触发（先做 1-2 条规则，如肾→眼）+ 分歧检测 v0** + 实验三对比实验 | 实验三有 ≥10 个案例结果 |
| Week 4 | 会诊过程可视化 + 精选案例会诊卡 + 演示视频/文档 | 全材料齐（对照备赛手册清单） |
