# 流程影响评测数据字典（workflow-impact.v1）

## 用途与边界

这份字典用于比较同一批脱敏病例在“人工整理”和“系统辅助整理”条件下的流程工作量与可用性。它不评价诊断正确性、治疗效果或临床结局，也不能把流程耗时差异解释成患者获益。

输入使用 JSONL，每行一条观察记录。`pair_id` 和 `participant_id` 必须是不可逆、无业务含义的随机标识；不能由姓名、手机号、病例号、主诉或病史直接生成。脚本拒绝不在白名单内的字段，因此不能把患者原文、报告正文、评审自由笔记写入评测汇总。

## 配对执行协议

1. 从脱敏病例池中抽取病例，给每例生成随机 `pair_id`；同一病例在人工组和系统组各完成一次相同整理任务。
2. 参与者先完成培训题，再按随机或拉丁方顺序执行两种条件，避免固定顺序带来的熟练度偏差。两次之间清除上一条件的摘要和页面状态。
3. 人工组由评测者使用统一的人工整理表完成；系统组使用当前患者四阶段流程和医生审核台。两组使用同一份任务说明和相同的资料包。
4. 患者端记录四阶段起止时间、返回/错误/展开次数、摘要查找任务结果和 1–5 分可读性/理解度评分。医生端记录从打开病例到完成必审项的时间、必审项数、实际决定数、修改/驳回、分歧处理和资料往返。
5. 计时起点是参与者看到任务说明并点击开始；终点是完成规定任务并提交结果。暂停超过 5 分钟、切换到外部资料或违反操作协议时记录 `protocol_deviation=true`，该观察不进入配对差值。
6. 评审者应具备项目规定的医学背景或经过统一培训；报告记录资质类别和培训版本，不能把未具备资质的开发者评分写成医学质量证据。

## 顶层字段

| 字段 | 类型 | 要求 |
|---|---|---|
| `schema_version` | string | 固定为 `workflow-impact.v1` |
| `pair_id` | string | 随机匿名配对标识；同一脱敏病例的两种条件相同 |
| `participant_id` | string | 随机匿名参与者标识；不能包含真实身份 |
| `actor` | enum | `patient` 或 `doctor` |
| `condition` | enum | `manual` 或 `system` |
| `outcome` | enum | `completed`、`failed` 或 `excluded` |
| `duration_sec` | number | 从规定起点到终点的秒数；完成记录必须大于 0，最长 24 小时 |
| `protocol_deviation` | boolean | 是否发生协议偏离；为 true 时不进有效配对 |
| `issue_code` | string | 可选的受控错误/失败代码，不写自然语言 |
| `operations` | object | 可选的非负操作计数，键只能来自脚本白名单 |
| `patient` / `doctor` | object | 只填写与 `actor` 对应的对象 |

## 患者对象

| 字段 | 含义 |
|---|---|
| `stage_seconds` | `fill`、`verify`、`advice`、`summary` 四阶段分别耗时 |
| `stage_completed` | 四阶段是否完成 |
| `summary_tasks_total` / `summary_tasks_found` | 摘要查找任务总数与正确找到数；只记录数字 |
| `summary_readability_score` | 1–5 分可读性评分 |
| `summary_comprehension_score` | 1–5 分“知道下一步做什么”理解度评分 |

## 医生对象

| 字段 | 含义 |
|---|---|
| `required_review_items` | 该病例按当前审核分级要求必须处理的条目数 |
| `reviewed_items` | 实际完成决定的条目数 |
| `modified_items` / `rejected_items` | 修改和驳回的条目数 |
| `disagreement_items` / `disagreements_resolved` | 发现的分歧数与已处理分歧数 |
| `high_risk_items` / `high_risk_reviewed_items` | 高风险必审条目数与其中实际完成决定的条目数；用于计算未复核高风险条目，不作临床漏诊率 |
| `missing_info_round_trips` | 因资料缺失导致的补充往返次数 |
| `specialty_expected_count` / `specialty_covered_count` | 任务清单中的应覆盖科室数与实际呈现数；这是流程覆盖，不是临床召回率 |

## 计数与排除口径

- 完成率分母是该条件下所有有效启动记录；失败和协议偏离不被改写成完成。
- 配对差值只使用同一 `pair_id`、同一 `actor` 下人工和系统两侧都完成、无协议偏离、各只有一条记录的观察。
- 缺一侧、重复记录、失败、显式排除和协议偏离分别计数；不能用 0 代替缺失指标。
- 未记录某个可选指标时，输出 `not_recorded`，不当作 0。
- 真实评测报告必须列出数据来源、脱敏方式、样本量、参与者资质、失败、排除、分母和局限；dry-run 只能验证脚本，不形成产品收益结论。
