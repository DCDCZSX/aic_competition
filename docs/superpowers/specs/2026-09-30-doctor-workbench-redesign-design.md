# 医生端极简临床工作台设计规范

## 1. 目标与边界

### 目标

将医生端从“信息全部同时展示”的三轨工作台，收敛为以审核决策为中心的单列临床工作台，降低医生定位重点、理解依据和完成操作的认知成本。

### 已确认事实

- 医生端当前包含病例列表、病例总览、分诊依据、证据板、MDT 审阅、报告审核、审核历史 7 个视图。
- 宽屏当前使用左导航、主内容、右侧上下文面板的三轨结构。
- 病例队列当前同时展示多个状态、可靠性、分析和处理字段。
- 审核页包含必审、抽查、已完成、自动处理等分组，并在右侧重复承载进度、发布和须知。
- 后端接口、权限范围、病例分科路由和审核动作已经存在，本次只调整医生端的信息架构和呈现层，不改变业务规则。

### 非目标

- 不删除后端返回的原始资料、AI 分析、证据、审核历史或审计记录。
- 不改变病例分配、科室权限、审核状态流转、发布条件和接口契约。
- 不引入第三方 UI 框架或外部资源。

## 2. 核心设计原则

1. **先决策，后解释**：首屏只放能帮助医生做当前决定的信息。
2. **默认少量，按需展开**：原始分析、完整证据和审计细节默认折叠。
3. **一条主路径**：医生从病例进入后沿“总览 → 判断依据 → 多学科 → 审核发布”完成任务。
4. **一个区域一个目的**：避免卡片套卡片、同一状态在多个区域重复出现。
5. **不以颜色替代语义**：风险和状态始终同时显示文本标签。
6. **保留完整性，不强迫阅读完整性**：数据保留，首屏阅读量减少。

## 3. 信息架构

### 3.1 顶层导航

病例队列独立作为入口。进入病例后，将现有 7 个视图收敛为 4 个主要任务入口：

1. **总览**：病例概况、当前状态、风险和下一步。
2. **判断依据**：分诊结论、证据关联和信息缺口。
3. **多学科**：共识、分歧、待确认问题和专科意见。
4. **审核发布**：待审条目、处理动作、发布审核版。

“审核历史”和原始专科分析作为次级入口，通过折叠区或“查看详情”进入，不与主要任务平级争夺注意力。

### 3.2 页面骨架

病例详情不再使用固定右侧面板。统一采用：

```text
病例上下文头部
任务导航
当前任务内容
次要操作与审计信息
```

病例上下文头部固定显示病例编号、牵头科室、风险、审核状态和当前主要操作。主内容保持单列阅读宽度；只有真正需要比较的内容才使用局部两列。

## 4. 各页面内容取舍

### 4.1 病例队列

默认列只保留：病例、主诉/牵头科室、风险、处理状态、更新时间。

可靠性等级、分析数量、自动处理数量和细分状态移入病例行展开详情。左侧筛选保留三个常用入口，其余筛选放入“更多筛选”。

主要操作只有“打开病例”；批量补齐、批量处理等低频操作放入工具菜单。

### 4.2 总览

首屏只展示：一句话病例概况、当前风险、审核状态、一个最重要待办和下一步按钮。

完整患者画像、用药、检查明细和信息缺口通过分组展开。总览不重复渲染分诊、证据和审核页面已经出现的长内容。

### 4.3 判断依据

默认展示：主要分诊结论、牵头科室、选择理由、影响当前决定的信息缺口。

规则命中、模型中间过程和完整证据列表进入“查看依据”折叠区。证据板按“当前判断 → 直接证据”组织，而不是先展示完整时间线。

### 4.4 多学科

默认展示三类结果：共识、分歧、待确认问题。

各科室 AI 原始意见统一放入“专科意见”折叠区。宽屏可将三类结果做成局部对照布局，中等屏幕和移动端自动改为上下排列。

### 4.5 审核发布

页面顺序固定为：

1. 紧凑审核进度摘要。
2. 需要医生决定。
3. 建议抽查（默认折叠）。
4. 已完成审核（默认折叠）。
5. 自动处理（默认折叠）。
6. 发布审核版与线下医生意见。
7. 审核须知（默认折叠）。

单条审核项默认只显示标题、当前 AI 建议、关键依据和操作按钮。分级原因、证据引用、历史决定、修订版本等进入“查看详情”。

### 4.6 审核历史

默认使用版本时间线：版本、操作人、时间、变更摘要。具体字段差异和审计原文按条目展开。

## 5. 视觉与排版系统

- 保留现有暖色编辑风和共享 token，不更换品牌色体系。
- 主内容使用单列阅读宽度，避免三轨同时压缩正文。
- 减少边框、阴影和重复背景层；普通分组优先依靠间距和标题层级区分。
- 每个页面最多一个主按钮，次要按钮使用低对比样式。
- 标题、说明、正文、元数据控制在有限的字号层级内。
- 橙色只用于主要行动和需要关注的风险；信息、警告、成功状态同时显示文本。
- 不新增装饰性插画、渐变背景或无业务意义的图标。

## 6. 响应式规则

- 宽屏：左侧仅保留病例队列筛选；病例详情主内容使用单列，局部比较区最多两列。
- 中等屏幕：隐藏固定右栏，不为不存在的栏位预留空白；操作区回到主内容中。
- 移动端：任务导航变为横向滚动或折叠菜单；所有比较区上下排列；审核动作保持可触达。
- 所有折叠内容必须可键盘访问，并保留明确的展开状态和焦点样式。

## 7. 兼容与数据策略

- 保留现有 DOM 关键 id、JS 状态字段和 API 调用，避免破坏审核动作及现有自动化测试。
- 对内容做显示层裁剪，不在前端删除后端字段。
- 若数据为空，显示简短空状态，不展示大段解释性文案。
- 低权限科室医生继续只看到授权病例；总审医生继续看到全量病例。

## 8. 实现顺序与验证

1. 先调整医生端骨架、任务导航和队列密度。
2. 再重构总览、判断依据和 MDT 的默认可见内容。
3. 最后重构审核发布和历史记录的内容层级。
4. 每个阶段保留现有行为测试，并新增默认折叠、单列布局、响应式和权限范围断言。
5. 完成后运行前端逻辑测试、结构/响应式测试、`git diff --check` 和 Impeccable mechanical detector。

## 9. 验收标准

- 医生打开病例后，首屏能明确看到当前状态和唯一主要任务。
- 任何主要页面默认不同时展示两层以上的嵌套容器。
- 审核页默认可见内容仅包含待医生决定所需信息。
- 原始分析、完整证据、历史决定仍可在两次操作内访问。
- 宽屏、中等屏幕和移动端均不出现固定右栏挤压主内容或操作不可达。
- 现有病例分科、权限、审核、发布和审计功能测试继续通过。
