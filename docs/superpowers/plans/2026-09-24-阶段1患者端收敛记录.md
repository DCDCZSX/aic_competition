# 阶段 1：患者端流程收敛记录

日期：2026-09-24（Asia/Shanghai）  
对应计划：2026-09-23-MDT产品流程收敛开发计划.md  
状态：患者端四阶段收敛已实现；本次补充第三阶段统一分析进度与结果展开规则。

## 1. 实现范围

### 报告阶段语义

- Report 序列化新增 stage、stage_label、review_status、review_status_label 和 report_version。
- doctor_confirmed 的原有含义保持不变；只有病例进入 doctor_confirmed 后才显示医生审核阶段。
- 未发布病例显示“AI 就诊准备摘要/报告”；已发布病例显示“医生审核版摘要/报告”及版本号。
- Markdown 打印标题和患者端报告横幅使用同一套阶段文案。

### 患者四阶段

- 主导航从 9 个内部页面收敛为四个用户阶段：
  1. 填写情况：就医目标（可跳过）和资料录入合并为一个填写栏目；
  2. 核对资料：结构画像确认和必要追问，脱敏在后台自动完成；
  3. 查看建议：分诊方向、路径任务和专科 AI 参考意见；
  4. 生成就医摘要：精简摘要、完整报告、打印/导出。
- 原子面板仍保留在对应阶段内，以便异步状态和返回修改；导航和主屏不再要求患者逐屏完成 9 次。
- 第 1 阶段删除“系统会做什么/不会做什么”、资料示例、脱敏原因和提交后流程说明；这些内容不参与填写决策，避免增加阅读负担。
- 就医目标和病情资料共用底部唯一主按钮，删除“直接开始录入资料”这一层重复点击。
- 病情资料改为单栏展示，仅保留粘贴/表单、主要问题和必要的隐私提醒。
- 患者端恢复 localStorage 会话前先请求 `/api/me` 验证；预览接口返回 401/400 时展示服务端原因，失效会话自动清除并回到登录页。
- 第 2 阶段不再展示独立的“提交前脱敏预览”面板；点击第 1 阶段继续后由后台自动完成脱敏、PII 拦截和一次性凭证校验，安全通过后直接进入结构画像。
- 第 2 阶段将结构画像和关键问题同屏展示，删除“画像无误，继续”这一层确认；回答提交后进入第 3 阶段，在页面顶部显示资料整理、就医方向和相关科室建议的统一进度条。后台轮询实时更新状态，路径、任务和报告入口等进度完成后再展开，避免等待时看起来像卡住或误看旧结果。
- 第 3 阶段只向患者展示建议的就医方向；就医路径和任务合并为一栏，任务紧跟对应路径步骤展示。
- 第 3 阶段的 AI 多学科意见改为通俗的“科室关注点 + 参考提示”卡片；规则命中、模型受限发言、置信度、共识/分歧、向医生确认问题和不确定项只保留在医生端数据，不在患者端默认展示。
- 第 3 阶段的方向、路径任务和专科参考意见在同一页连续展示，删除“查看就医路径与任务”和“查看 AI 多学科分析”两个重复跳转按钮。
- 第 3 阶段删除方向、路径和专科卡片内部的返回按钮，只在页面底部保留“返回核对资料”和“查看就医报告”。
- 报告生成后将病例标记为“主流程已完成”：左侧四个阶段全部可点击回看，进度条保持 100%；如果补充就诊后资料使报告失效，则恢复按当前进度逐步开放。
- 就诊后资料更新、变化摘要和收尾仍作为主流程之后的独立入口。
- 移除患者端常驻右侧病例上下文栏和窄屏重复上下文栏；病例号和审核状态保留在顶栏，详情回到当前阶段展示。

### 报告和视觉层级

- 一页摘要只保留主要问题、关键资料、影响下一步的信息缺口、咨询方向、待向医生确认的问题和当前任务；空列表不再反复显示“暂无”。
- 可靠性和技术校验细节不进入默认摘要，完整报告仍保留证据、专科视角、时间线和审核记录。
- 完整报告继续默认折叠，支持目录、展开全部和打印前全展开。
- 患者阶段卡增加统一阶段标题、分隔和较少的嵌套边框；通用 select 外框明确保持 12px 圆角。
- 医生端现有队列/病例/审核结构和无衬线工作台字体通过现有回归检查，阶段 1 未改动医生业务流程。
