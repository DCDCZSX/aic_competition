# MDT 初筛与病例分流 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有医生审核台前增加可审计的 MDT 初筛子流程，让医生决定病例进入单专科、MDT、补资料或急症处理，并向患者提供安全的下一步提示。

**Architecture:** 初筛数据保存为病例 `payload.mdt_screening`，不扩展现有病例状态机。新增 `CaseFlow.submit_mdt_screening()` 负责清洗、科室域校验、持久化和审计；Flask 路由沿用 `_guard_doctor_case()` 做医生角色和病例授权校验。医生总览页显示并提交初筛表单，患者病例接口只返回去除内部审核人字段后的安全视图。

**Tech Stack:** Flask、SQLite、现有 `CaseFlow`、`Store`、`department_domain`、标准库 unittest、现有医生端前端模板。

**Spec:** `docs/superpowers/plans/2026-09-23-MDT产品流程收敛开发计划.md` 任务 2。

## Global Constraints

- 初筛是病例数据中的流程子状态，不向 `case_state` 增加新状态。
- 只有已登录且已获病例授权的医生可以提交初筛；未登录和患者会话必须被拒绝。
- 初筛原因必须经过现有脱敏/内容校验后再落库；审计不记录未脱敏原文。
- 科室必须通过 `services.department_domain` 解析；域外科室不能静默接受。
- 患者端不得看到 `reviewer_id`、医生账号或内部权限信息。
- `urgent_care` 不得进入普通 MDT 队列；现有急症提示文案作为下一步提示来源。
