# 流程影响评测 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立一套不接触患者原文、能比较人工整理与系统辅助整理的配对评测工具，并诚实报告患者流程可用性、医生工作量和分歧保留情况。

**Architecture:** 使用标准库实现离线 JSONL 读取器和汇总器。每条记录是一名评测参与者在一个脱敏病例上的一次观察，使用不可逆的 `pair_id` 配对人工组与系统组；脚本只接受结构化计时、操作数、任务结果和 1–5 分评分，拒绝原始病例文本与未知字段。汇总输出 Markdown 和 JSON，分别列出有效样本、未完成、重复、缺字段和异常值，不从缺失数据推算收益。

**Tech Stack:** Python 3 标准库、`unittest`、JSONL、Markdown。

**Spec:** `docs/superpowers/plans/2026-09-23-MDT产品流程收敛开发计划.md` 的任务 9；补充设计写入 `docs/评测实验设计方案-MDT.md`。

## Global Constraints

- 所有评测输入必须是脱敏病例的匿名 ID；不得写入姓名、主诉、病史、报告正文、自由文本或可逆映射表。
- 配对比较只报告流程和工作量指标；不得把结果表述为诊断准确性、临床疗效或节省时间的证明。
- 手工组与系统组必须使用同一病例配对；缺少一侧、重复观察、失败或协议偏离的记录进入排除表并保留原因。
- 患者端四阶段、摘要可读性、医生实际审核、必审条目、资料往返和分歧保留分别定义分母。
- 当前没有真实人工评测数据时，只运行合成 dry-run 验证脚本，不把 dry-run 数字写成产品证据。
