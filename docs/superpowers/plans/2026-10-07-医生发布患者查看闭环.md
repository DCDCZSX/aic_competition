# 医生发布、患者查看的结果闭环

目标：移除患者端末尾的就诊后补充步骤，改为由医生审核、填写最终建议并发布，患者查看最新发布结果。

产品判断：患者补充客观检查资料与医生确认意见是不同职责。当前末尾实际提供新资料补充，而医生端已有意见录入入口；本轮按用户授权收敛末尾，不把线下已就诊等同于系统审核完成，也不把未发布内容标记为最终建议。复诊资料独立入口以后按需求设计。

实现沿用 Flask、内联 JS、现有病例鉴权、审核门禁、串行病例事务和不可变报告快照，不引入依赖。

- [x] 先写行为回归：发布最终建议、版本保存、发布前不作为最终结果、患者不能发布、旧报告刷新与病历列表重开。
- [x] 医生发布接口要求非空最终建议，服务层校验并脱敏，和审核版本同一次发布保存；保留内部旧调用兼容。报告包含发布状态、建议和发布者/时间，全文及打印带入已发布建议。
- [x] 医生发布面板改成先填写患者可读最终建议再发布；已发布版本只读，现有必审、分歧及 MDT 门禁继续生效。
- [x] 患者移除补充/变化步骤及相关脚本，第四阶段显示审核状态与医生结果，报告每次打开/刷新重新获取；从病例列表打开已有报告不受本次分析进度限制。
- [x] 更新对应结构/行为测试及文档，在隔离后端用真实患者、医生角色验证发布闭环和手机/桌面布局；记录验证边界。

文件：`backend/app.py`、`backend/services/case_flow.py`、`backend/services/report_service.py`、`backend/templates/patient.html`、`backend/templates/doctor.html`、相关测试与验收工具、开发交接及患者/医生 UI 说明。

验证边界：使用合成病例、内存数据库与临时上传目录，不操作用户的真实病例，不调用外部模型。现有资料更新后端和历史数据保留，用于既有医生资料链路；患者末页移除该交互。

验证结果：相关 Python 回归 329 项通过，前端行为 152 项通过；实际角色与真实接口在 1440px、390px 下完成审核/建议必填/发布/患者刷新/打印/病历列表重开。患者通过主动刷新或重开获取最新结果，本次未添加推送通知。旧版已发布报告缺少最终建议时明确展示缺失提示，不虚构意见。
