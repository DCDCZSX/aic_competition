# 分流确认前置实施方案

**目标：** 将主责/协同科室的首次医生决策前置到“分流确认”，让正式 MDT 和报告审核只引用已经确认的方向。

**已确认问题：** 旧逻辑在 `review_service.build_items()` 中把 AI 分诊结果生成“科室入选”必审项；分流页没有保存医生确认，导致科室决策延迟到报告审核。

**实施内容：**

1. 新增 `triage_doctor_confirmation` 数据和 `POST /api/v2/case/<id>/triage-confirmation` 接口，保存主责科室、协同科室、理由、确认人和时间。
2. 分流确认页增加主责/协同选择和保存入口，明确报告审核不再重新决定科室。
3. 正式 MDT 启动必须先有分流确认，且参与科室只能来自已确认方向。
4. 有新确认记录的病例不再生成“department_selection”报告审核项；旧病例暂保留兼容读取，发布前仍要求完成分流确认。
5. 报告的“分诊结果”读取医生确认方向，正式 MDT 完成记录追加到“医生最终意见”。
6. 患者端不暴露医生确认人的内部字段。

**验证：** 定向 Python 测试、前端结构测试、前端逻辑测试和 JavaScript 语法检查；已知 `test_backend_optimization` 中存在与本改动无关的基线失败，单独报告，不将其混入本功能结论。
