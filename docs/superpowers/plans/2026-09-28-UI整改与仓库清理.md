# UI 体验整改与仓库清理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 分阶段修复患者端与医生端已确认的可访问性、响应式、视觉层级和性能问题，同时只清理经过引用审计的生成物，不破坏比赛主链路、历史依据或评测资产。

**Architecture:** 继续使用现有 Flask 模板、共享 CSS token 和原生 JavaScript，不引入前端框架或新的 UI 依赖。先建立可回归的结构约束，再按“语义与键盘 → 移动端 → 视觉层级 → 性能 → 仓库卫生”的顺序收敛；每一阶段都保持四阶段患者流程和医生审核台的现有业务接口不变。

**Tech Stack:** Flask/Jinja 模板、原生 HTML/CSS/JavaScript、`backend/static/css/tokens.css`、`backend/static/css/dsh.css`、Python `unittest`、Node `--check`、Git。

**Spec:** `docs/UI设计说明-患者端.md`、`docs/UI设计说明-医生端审核台.md`、`docs/开发进度与交接.md`、本次 UI 审查结论。

> **后续决策说明（2026-10-03）：** 医生工作台不再保留“当前主要任务”说明条，也不在历史记录页展示完整审计日志；医生端改为直接呈现关键流程记录，完整审计数据仍由后端保留。

## Global Constraints

- 保持患者端四个主阶段：填写情况、核对资料、查看建议、生成就医摘要；第二阶段完成后不重复显示底部总进度条。
- 患者默认先看到一页摘要，完整报告继续可展开、打印；不得为了缩短内容而删除下一步行动、风险提示或就诊准备信息。
- 所有 AI 内容继续显示“AI 辅助分析 · 尚未经医生审核”等状态；不在患者端展示医生工作台内部的逐科推理过程。
- UI 颜色必须来自共享 token；医疗风险、警告和焦点状态需要同时满足可读性与可辨识性。
- 不修改或删除 `_legacy/`、`knowledge_base/`、`eval_out/`、`MDT-5*.csv`、`offline_packages/`、`offline_packages.tar.gz`、官方规则 PDF、历史评测与交接文档。
- `start_mdt.py`、`start_batch_mdt.py`、`batch_mdt_processor.py`、`backend/services/mdt_service.py`、`backend/services/mdt_agents.py` 属于旧链路或评测扩展；虽然不是比赛主链路，不在本次清理中删除。
- 任何删除动作必须先有代码/文档引用扫描结果；没有证据证明冗余的文件只记录为“保留并说明原因”。

## 已确认的问题边界

以下问题来自现有模板、CSS、静态回归和人工走查；它们是需要按优先级处理的产品改进项。impeccable 检测器在当前环境缺少部分解析模块，输出中的“侧边强调线”和“进度条宽度过渡”属于现有设计意图，不能直接当成缺陷。

| 优先级 | 问题 | 主要位置 | 目标结果 |
|---|---|---|---|
| P1 | 登录输入依赖 placeholder，目标卡/选项使用可点击 `div`/`span`，医生导航存在无 `href` 锚点 | `backend/templates/patient.html`、`doctor.html` | 原生 label、form、button、链接和完整键盘操作 |
| P1 | 正文、警告、焦点环的对比度不足 | `backend/static/css/tokens.css` | 正文与交互状态达到 WCAG AA 目标，状态色不只依靠颜色区分 |
| P1 | 小按钮、分页、chip 在触屏下小于 44px | `backend/static/css/dsh.css`、两端模板 | 主要触控目标最小 44×44px，视觉尺寸可通过内边距实现 |
| P1 | 医生队列表格窄屏隐藏表头，单元格没有字段标签 | `backend/templates/doctor.html` | 窄屏改为可读卡片或带 `data-label` 的行 |
| P1 | 审核弹窗和动态错误消息缺少 dialog/live region 语义 | `doctor.html`、`patient.html` | 焦点进入、关闭后返回原控件，错误可被读屏器立即获知 |
| P2 | 患者第三阶段信息块过密，路径、任务、MDT 和警告同时展开 | `patient.html` | 保留下一步行动，路径/MDT 在窄屏折叠，警告合并 |
| P2 | 医生工作台三栏同时暴露太多操作 | `doctor.html` | 增加当前主要任务提示，右栏无内容时收起，关键发布操作始终可达 |
| P2 | 医生模板存在硬编码背景色和较多 inline style | `doctor.html` | 颜色回收到 token/class，避免主题漂移 |
| P2 | 患者分析轮询、医生 MDT 定时器和整块 `innerHTML` 重绘缺少退避 | 两端模板 | 页面不可见时暂停，失败时退避，更新局部节点 |
| P2 | 登录区没有真正的 `<form>` 提交行为 | 两端模板 | Enter 键提交、错误关联到输入框、按钮状态可感知 |

## 文件与职责地图

- `backend/templates/patient.html`：患者登录、四阶段内容、追问、分析状态、摘要/完整报告和更新闭环。
- `backend/templates/doctor.html`：医生登录、病例队列、画像/证据/MDT/审核弹窗和发布入口。
- `backend/static/css/tokens.css`：颜色、间距、字号和语义变量的唯一来源。
- `backend/static/css/dsh.css`：共享布局、按钮、模态框、断点和打印样式。
- `backend/tests/test_frontend_structure.py`：页面结构、路由和关键语义的静态回归。
- `backend/tests/test_responsive_layout.py`：断点、窄屏布局、患者报告和医生主区兜底操作的回归。
- `backend/verify_frontend_logic.mjs`、`backend/verify_report_render.mjs`：浏览器外的 JavaScript 语法与报告渲染验证。
- `docs/开发进度与交接.md`：仓库边界、历史资产和阶段状态的事实来源；清理后只补充已完成的卫生项。

## 清理结论（本次审计）

- **可以直接清理：** 仓库与注册工作树中的 Python `__pycache__/` 和 `*.pyc`。它们是被 `.gitignore` 忽略的运行缓存，不被代码或文档作为输入使用。
- **不能直接清理：** `_legacy/`、`knowledge_base/`、评测 CSV/输出、离线安装包、`environment.txt`、旧链路脚本和三个已注册工作树。交接文档明确记录了它们的历史、评测或分支用途。
- **暂不删除业务源码：** 当前没有发现一个同时满足“无代码/文档引用、非评测资产、非历史留档、删除后不影响启动或测试”的已跟踪业务文件；删除 `mdt_service.py`、`mdt_agents.py` 或批处理脚本会直接破坏旧链路测试/评测入口。

### Markdown 文件的保留边界

| 分类 | 文件或目录 | 结论 | 原因 |
|---|---|---|---|
| 当前规范 | `README.md`、`docs/README.md`、`docs/开发进度与交接.md`、`docs/产品开发规格书-比赛版v-competition.md`、`docs/多学科就医智助系统-产品设计方案-v3.0.md`、两份 UI 设计说明 | 保留 | 启动说明、唯一进度源、产品/开发规范和实现对照都依赖这些文档 |
| 当前评测与交付 | `评测v0/v1结果与改进方向.md`、`docs/评测v2结果与改进方向.md`、`docs/评测实验二三结果与改进方向.md`、`docs/评测流程影响*.md`、`docs/演示脚本与材料清单.md`、`BATCH_README.md` | 保留 | 评测脚本、交接记录和演示材料清单引用其中的口径与数字 |
| 历史审计 | `docs/_archive/`、`docs/考古报告-MDT原型.md`、`_legacy/README.md`、`docs/pr/`、`.superpowers/sdd/` | 保留 | 用于解释旧架构、评审意见、PR 决策和验收证据；交接文档存在直接引用 |
| 可候选归档 | `后端审查与优化建议.md`、已完成的 `docs/superpowers/plans/*.md` | 暂不删除 | 部分内容已被 `后端优化说明.md` 或交接文档吸收，但尚未完成“合并内容、更新引用、核对 Git 历史”的归档流程；应先移入统一归档区，再决定是否从工作树移除 |
| 工作树副本 | `.worktrees/*` 下重复出现的 Markdown | 不单独删除 | 这些文件属于 Git 注册工作树；应按分支整体处理，不能只删除其中的文档造成工作树不完整 |

因此，Markdown 文件不是因为“没有被程序 import”就能删除。当前能直接清理的是生成缓存；Markdown 的删除至少还要满足：内容已合并、引用已迁移、历史证据有替代位置、对应工作树或分支已不再使用。

本清单用于跟踪按阶段实施的 UI 修改与清理验收；代码变更仍需经过对应测试和独立提交后才算阶段完成。
