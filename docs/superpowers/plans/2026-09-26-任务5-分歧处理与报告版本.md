# 分歧处理与不可变报告版本 Implementation Record

> **目标：** 让牵头医生可以明确记录专科分歧的处理决定，并让每次发布的审核报告成为可追溯、不可覆盖的版本快照。

## 已完成

- [x] 分歧处理支持 `resolved`、`unresolved_with_followup` 和 `need_more_info` 三种状态；已解决必须填写选择/结果和理由，未解决必须填写下一步。
- [x] 增加 `POST /api/v2/case/<case_id>/disagreements`（兼容别名 `/disagreement-decisions`），沿用医生病例权限并写入审计记录。
- [x] 报告展示分歧状态、牵头医生决定、处理理由、下一步、责任审核人和处理时间；没有医生处理记录时仍保留 AI 聚合的分歧和待处理状态。
- [x] 增加可重复初始化的 SQLite `report_versions` 表；发布时保存病例编号、版本、发布人、发布时间、审核摘要、报告 JSON、摘要 Markdown 和完整报告 Markdown。
- [x] 发布门禁要求必审项和每个当前分歧都有明确状态；未解决分歧可以发布，但必须带后续安排。
- [x] 报告快照和病例状态转移在同一个串行病例事务中保存；重复版本不能覆盖原记录。
- [x] 增加 `GET /api/v2/case/<case_id>/versions` 和审核历史中的版本列表。医生可读取报告内容，患者只读取版本元数据和本次审核变化所需的摘要。
- [x] 没有历史快照的旧病例返回空版本列表，不为旧数据伪造历史。

## 主要实现

| 文件 | 内容 |
|---|---|
| `backend/services/review_service.py` | 分歧状态枚举、字段校验和最新决定归并 |
| `backend/services/store.py` | `report_versions` 表、快照写入及版本查询 |
| `backend/services/case_flow.py` | 分歧决定接口、发布门禁、快照生成、历史读取和队列摘要 |
| `backend/services/report_service.py` | 把分歧处理记录编入医生报告和患者可见摘要 |
| `backend/app.py` | 分歧决定和版本历史 API 路由 |
| `backend/templates/doctor.html` | 医生端分歧处理控件、发布提示和版本历史 |
| `backend/templates/patient.html` | 患者端已保存版本的变化摘要 |
