**提交流程（2026-09-11 调整：批量提交，避免 PR 碎片化）**：

- **开发过程中不提交**，改动累积在工作区（避免一天开出一堆小 PR）；
- 团队说"**今天工作做完**"后，统一执行一次提交 + 推送 + 开**一个** PR：

```bash
git fetch origin --prune

python -m unittest discover -s tests          # ① 测试必须全绿
Copy-Item E:\aic_competition\*.md CHAIS\docs\ # ② 同步文档快照
git add -A
git commit -m "<type>(<scope>): <当天成果说明>"
git push -u origin <type>/<name>
# ③ 在 GitHub 网页开 PR → main（描述里附验收证据：测试输出/评测数字）
```

- PR 粒度：**一个工作日 / 一个阶段成果 = 一个 PR**；PR 内可含多个文件的改动。
- 合入后：`git checkout main && git pull`，并回来更新本文件 §5 状态与 §9 变更日志。

**提交信息规范**：`<type>(<scope>): <subject>`
- type：`feat` 新功能 / `fix` 修缺陷 / `chore` 杂项 / `docs` 文档 / `refactor` 重构 / `test` 测试
- 示例：`feat(guardrail): 危象词表扩充至 42 条并加组合规则`

**PR 粒度**：**一个小功能/修复 = 一个 PR**；同一功能内的多个小改动可以在**同一分支、多个 commit**里，避免每个 commit 都开新 PR 造成噪音。PR 描述必须包含：改了什么 / 怎么验证 / 是否触碰红线。

**提交纪律（硬约束）**：
1. **绝不直接 push `main`**；
2. **绝不提交密钥与真实病例数据**——`.gitignore` 已挡 `.env`、`MDT-5*.csv`、`eval_out/`、`knowledge_base/`、`offline_packages*`，新增大文件前先确认是否该忽略；
3. 每个 PR 合入后**必须**回来更新本文件 §5 状态与 §9 变更日志；
4. 触碰 §3 禁改区的改动，PR 描述里写明队友确认。

**改文件的操作纪律（2026-09-12 血泪教训）**：
- ⛔ **不要用 PowerShell 的 `Get-Content`/`Set-Content`/`Out-File` 管道去改含中文的源文件**（本机默认代码页会把 UTF-8 当成 GBK 往返，`templates/patient.html`、`templates/doctor.html` 曾被整体写成乱码、并吃掉中文旁的引号）。
  - 读文件用 `read` 工具；改文件用 `edit`/`write` 工具；必须脚本化时用 **Python 且显式 `encoding='utf-8'`**（读写都显式）。
  - 已损坏时的抢救顺序：① 从**运行中服务的模板缓存**取回（`debug=False` 时 Jinja 缓存命中旧干净版本）→ ② 用 `edit` 重放改动 → ③ `node --check` 校验内联 JS + 用 Python 检查 `\ufffd` 与乱码特征串（`鏅鸿兘`、`璺緞`、`锛`）。
- ⛔ **抽取/替换公共样式时，先逐条确认被删掉的原规则里有没有承担布局职责的声明**：把患者端/医生端的内联 `<style>` 换成公共 CSS 时，顺手删掉了 `#login{display:flex;align-items:center;justify-content:center;min-height:100vh}` 中的居中与满高，导致登录卡片退化成左上角一块、整屏几乎全空（业务测试与结构测试当时都发现不了，靠肉眼才看出来）。现在结构测试里加了 `test_login_pages_are_full_bleed_two_column` 兜底。
- 改完模板后**必须**重启服务（`debug=False` → 模板有缓存），否则看到的还是旧页面。
- ⛔ **模板里禁止出现 `{#`**：Jinja 把 `{#` 当成注释起始，导致 `TemplateSyntaxError: Missing end of comment tag` → **整页 500**（业务单测全绿也发现不了，因为单测不渲染模板）。
  - 踩坑实例：CSS 里写 `@media (min-width:1100px){#ask-body{…}}` 触发；正确写法是 `{ #ask-body{…}`（`{` 后加空格）。
  - 已加回归测试：`tests/test_frontend_structure.py` 会扫描三页模板 + 渲染后的 HTML，任何 `{{` / `{%` / `{#` 残留直接失败。
- ⛔ **结构化输出（JSON）绝对不能走 Markdown 清理，也不能不看 `finish_reason`**：
  - `markdown_to_text()` 会把 ```json 包裹的整段内容**删掉**（`re.sub(r'```[\s\S]*?```','')`）、顺手改掉字符串里的内容 —— 对 JSON 输出是有害的。结构化调用一律走 `call_structured()`（内部用 `call_ai_api_raw()`，原文返回）。
  - `max_tokens` 写死 + 不检查 `finish_reason` 的后果：模型输出被**静默截断**成非法 JSON，现场只能看到一句"解析失败"，看不出真因。**每个结构化调用都要按实测给足预算**（血液科意见卡实测 2335 token → 预算 4000），并把 `truncated` 往上抛。
  - 已加回归测试：`tests/test_ai_service.py`（预算/截断检测/不做清理）、`tests/test_json_recovery.py`（**在任意位置截断都能恢复且不产生半个字符串**）。
- ⛔ **"可见的失败"必须同时"可操作"**：逐科失败如果只写成报告里的一句"本次未完成分析"，而不改变相位状态（相位仍 `done`），那"重新分析"会说"无需重试"、医生端批处理也会跳过 —— 用户被永久卡住。**凡是能失败的粒度，都要有对应粒度的重试**（本例：科室级失败 → `mdt.failed` + 相位 `partial` + 只重跑 mdt），并且**重跑成功后要清掉旧告警**，否则页面会一边说"已完成"一边挂着"未完成"。
- ⛔ **改写共享文件（CSS/模板）必须基于"工作区当前内容"，不要从 `git show HEAD:` 取原文再整体写回**：
  - 踩坑实例：抽取 token 的脚本 `dsh_text = git_show("HEAD:...dsh.css")` → 替换 `:root` → 整体写回，结果把该文件里**三处未提交的改动**（报告折叠样式、发布镜像、打印规则）一起冲掉了。`git status` 不会提醒你（文件本来就"已修改"）。
  - 兜底：只对**当前文件**做定点替换；批量改写前后各跑一次前端结构测试（这次正是它立刻报出 3 个失败）。
- ⛔ **布局/可达性缺陷要写成分档回归，不能只靠肉眼**：真实缺陷（<1440px 右轨收起 → 医生端发布入口消失）业务单测、接口测试、结构测试**全都发现不了**。现在 `tests/test_responsive_layout.py` 用一个小 CSS 求值器在 8 档宽度上断言"关键操作至少有一个可见入口"，并且**约定：右轨/侧栏里的关键操作必须有主区镜像**（`#rev-publish` ↔ `#rev-publish-inline`、`#ctx-panel` ↔ `#ctx-inline-panel`）。
  - 顺带记两条实现细节：解析 CSS 前**必须先剥注释**（否则 `/* 说明 */\n.rule{}` 会把注释粘进选择器），逗号分组选择器（`.appbar,.rail,.actions{display:none}`）要**拆开存**，否则 `display:none` 找不到。
